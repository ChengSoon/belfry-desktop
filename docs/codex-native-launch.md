# Codex 原生启动隔离模式

用途：当 Belfry 的自动 Codex 入口比「普通 PowerShell 终端里手动运行 `codex`」更容易报错时，用显式开关绕开托管启动附加项。此模式是可回退的隔离/缓解路径，不是加密推理解密修复，也不能保证消除中转的间歇性错误。

## 启用


首次升级后应结束旧的后台终端服务，或重启 Windows，避免新 GUI 仍连接到不认识此开关的旧守护进程。仅关闭应用窗口不一定结束后台服务。
必须使用包含此改动的新构建。在项目设置的环境变量中添加：

```text
BELFRY_CODEX_NATIVE=1
```

保存后在该项目新建 Codex 会话。已经运行的后台进程不会切换模式；重新连接同一个后台进程也不会改变它的启动方式。

也可以在启动 Belfry 的父进程中设置同名环境变量，作用于之后新建的 Codex 会话。项目中的显式值优先；设置为 `0` 可覆盖父进程中的 `1`。

## 行为与限制

- 新会话不附加自动绕过权限/沙箱的参数，使用 Codex 自己的权限配置。
- 恢复会话只传 `resume <明确的会话 ID>`，保留 ID 校验。
- 不附加 Belfry 插件 MCP，不签发协作身份或 Belfry Hook 连接。
- 协作模式不再附加 `--disable multi_agent` 或隔离的 `CODEX_SQLITE_HOME`。
- **不应用项目 Provider 覆盖，改为使用 Codex 的全局配置和调用方显式环境变量。** 项目隔离的中转与密钥不会在此模式下生效，请先确认全局配置是目标中转。
- 用户全局 MCP、全局 Hook、API 配置仍由 Codex 正常读取；此开关不会清除它们。
- 不删除/改写历史日志，不清除加密推理条目，也不关闭模型推理。
- Claude、Pi 和普通终端不受此开关影响。

需要完整协作/插件/项目 Provider 功能时，移除开关或设为 `0`，再新建会话。

## 验证边界

启动参数和附加项隔离有单元测试覆盖。Windows 下的真实中转故障需要实机复验：使用新会话比较默认自动入口、原生模式自动入口和普通 PowerShell 中手动 `codex`。单次没有报错不能证明间歇性故障已经修复。
