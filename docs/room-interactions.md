# 从房间顶部回答终端请求

房间会读取每个在线成员的 `readInteraction()`，无需等待粗粒度活动状态变成 waiting。
题目、可展开的上下文、选项标题和说明分别显示；当前光标只作提示，打开面板、轮询和切换语言
都不会选择答案。接口类型直接来自 `src/terminal/interaction.ts`，完整识别范围见
[终端交互契约](terminal-interactions.md)。

单选和确认由用户选择一项；多选先在本地编辑，点击提交才发送整个集合；输入支持多行、提交按钮
及 Ctrl/Cmd+Enter。仅原提示明确为 optional 时允许主动提交空答案。同请求的光标、勾选和状态
更新会刷新，已经编辑的多选和文本草稿仍按房间、成员、来源会话与请求 ID 保留。

窗口高度不超过 600px 时，顶部显示成员、请求数量和明确的处理入口。展开区在房间内部限高，
保留发送区及至少 80px 对话；选项内部可滚动。Tab 聚焦输入框时会在该区域内露出控件，避免
浏览器只滚动到第一行光标。Escape 先收起请求并回到入口；直接点击聊天保持点击位置和光标。
收起重开、跨窗口尺寸切换保留草稿、勾选和提交状态，待选请求存在时简报仍可展开和编辑。

提交前重新读取当前成员、目标、会话和请求。重复操作不会再次写入，来源变化或已关闭的请求
不能发给后续问题。已提交表示 PTY 写入成功；不确定结果保留终端核对入口，不自动重试。
可见编号分页显示“更多选项去终端查看”；隐藏/过滤的多选、已有终端输入草稿、截断命令上下文
和未知格式保留终端入口，不由房间猜测按键。

## 浏览器与执行验证

`rooms-choices.case.mjs` 的 37 项场景覆盖活动状态未更新时显示、同请求刷新、多个成员、

720×480 下的真实 Tab/点击、简报和聊天操作。

并在同一轮尺寸通知中读取聊天余量。旧版从 80px 降到 76px，修复后仍为 80px；原有场景的
80px、完整输入框、真实点击和发送断言及采样时序均保留。原始对照日志为
`/tmp/belfry-t36-resize-controlled-before.log` 和 `/tmp/belfry-t36-resize-controlled-after.log`。

`rooms-choice-execution.case.mjs` 通过实际 RoomView 控件、`TerminalInteractions`、
`PromptInput` 和 xterm 的 paste 路径连接独立 Node 消费进程，使用固定测试会话
`room-qa-pty`，不连接用户的终端。消费端只解释按键和报告结果，不执行屏幕上的示例命令。
