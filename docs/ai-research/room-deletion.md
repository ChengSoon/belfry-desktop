# 删除房间同时删除成员会话

核查日期：2026-11-15。用户要求删除房间时一起删除房间内所有 Agent，成员不再回到普通会话列表。

此前 `room_delete` 只删除房间记录及排队消息；成员会话仍存在于全局工作区，房间隔离名单更新后会恢复普通展示。

本次改动：

- 原生删除返回当前在场成员的 tab ID，包括统筹；已经移出房间的成员不在删除范围内。
- 房间移除与已删除成员 ID 在同一个原子提交中保存。存储升级到 v5，读取 v1–v4 时迁移；旧实例不会覆盖不认识的新版本。删除提交失败时不关闭终端、不撤销身份。
- 提交后取消成员的迟到创建、撤销协作身份、清理名册及待办，并按 tab ID 调用正常终端关闭路径，释放插件/A2A 连接。终端 I/O 在房间锁外执行；清理错误会返回界面。
- 前端一次移除所有相关 tab，全局会话存档、命名工作区和分屏引用随之对账。面板关闭后收到删除成功回执也会清理；轮询按原生删除记录清理旧存档，并持续隐藏已删除 ID。
- 原生创建和名册同步拒绝已删除的成员 ID，避免旧存档重新启动或重新登记这些 Agent。
- 更新中英文删除确认和协作说明。

主要实现：[房间存储](../../src-tauri/src/rooms/store.rs)、[删除命令](../../src-tauri/src/rooms/commands.rs)、[会话隔离与清理](../../src/rooms/useRoomBoundTabs.ts)、[生产界面回归](../../src/components/lazy/testing/rooms-deletion.case.mjs)。
