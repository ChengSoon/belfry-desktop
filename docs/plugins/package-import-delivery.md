## 目标与边界

用户可以选择 `.piplug` 包完成预览、安装和管理，无需单独准备或选择 `manifest.json`。
保留受管目录安装与开发目录加载，复用当前静态清单、权限及生命周期。
包内根目录仍需有清单，由插件作者提供。

- 支持 PI-Desktop 开发工具采用的 ZIP32 Store（不压缩）容器，扩展名 `.piplug` 或 `.zip`。
- 分别验证容器格式与 Belfry 静态插件清单；不把容器支持等同于现有 PI 插件 API 兼容。
- 预览只在内存读取；安装前重新读取包并核对文件快照，默认禁用，失败不留有效半安装。
- 显式拒绝加密、压缩、分卷、ZIP64、符号链接、路径逃逸、重复/冲突路径、损坏 CRC 与超额条目。
- 不新增依赖、不改根配置或共享协议；使用插件私有模块，沿用现有 IPC 参数与 registry。

## 风险与验证

归档读取属于输入边界，按测试驱动方式实现。使用标准 ZIP 工具生成的真实样例验证互通，
并覆盖目录/本地记录不一致、截断、路径冲突、CRC、压缩和配额等错误路径。
所有成员先校验再写入受管目录，禁止归档自行指定宿主文件目标或执行安装脚本。

范围：`src-tauri/src/plugins/**`、`src/plugins/**`、`examples/plugins/**` 及相关插件文档。
沿用 `executing-plans`、`test-driven-development`、审查清单与 `verification-before-completion`；
真实桌面验收使用 `computer-use`，完成后使用 `belfry done` 回报。

## 验收条件

1. 标准工具生成的示例包可预览、取消、安装、启用、重启恢复及卸载；原包保留。
2. 包内容在预览后改变时拒绝提交；坏包不产生受管副本或 registry 条目。
3. 目录安装和开发加载保持有效，开发加载不能引用归档文件。
4. 界面主安装入口选择插件包，清单不再作为普通用户导入步骤。
5. 对清单/运行时的实际支持范围描述准确，动态 PI 插件仍不被误报为可运行。

- 标准 ZIP 工具确认安装副本三个文件与原包相同；卸载后原包完整、受管目录为空。
