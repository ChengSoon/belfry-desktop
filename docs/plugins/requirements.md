# Belfry 插件系统产品需求

## 1. 定位与目标

让用户把常用 Agent 工作方法安装为可管理、可复用、可分享的功能集合，
无需每次复制长 Prompt，也无需为了增加一组工作流修改 Belfry 核心代码。

首期示例：导入“代码审查助手”，启用后在 Quick Open 搜索“审查改动”，
选择当前项目的 Codex/Claude 会话，填写审查范围，预览指令后发送；
也可在 Recipe 中运行“梳理需求 → 制定计划 → 检查结果”的多步模板。

产品成功标准：完整跑通“导入 → 审阅 → 安装 → 启用 → 搜索/选择 → 预览 → 投递 → 禁用/卸载”；
坏插件不妨碍 Shell、Agent 会话和其他插件；关闭重启后管理状态保持一致。
首期不建立遥测系统。测试人员记录安装成功率、首次运行耗时和恢复结果即可。

## 2. 用户与场景

| 用户 | 需求 | 首期承接 |
| --- | --- | --- |
| 普通使用者 | 一键装入别人分享的模板，清楚知道会发送什么 | 文件导入、内容预览、明确启用、运行预览 |
| 高频用户 | 快速调用团队惯用流程，按项目选择目标 | Quick Open、变量表单、会话选择 |
| 模板作者 | 用简单文件组织多个模板，升级不覆盖用户定制 | 版本化 manifest、校验错误、复制为我的 Recipe |
| 问题排查者 | 知道何时失败、如何恢复，不影响现有终端 | 状态原因、诊断、上一版本回退 |

用户故事 US-01：收到同事的文件，导入后能看到作者、版本、包含的所有动作，再决定安装。
US-02：Agent 忙时运行插件模板，内容按既有队列等待，不插入权限确认输入。
US-03：修改复制出来的 Recipe，更新插件后自己的内容保持不变。
US-04：安装错误版本后可以返回上一个有效版本，不重新配置所有插件。
US-05：卸载插件后入口消失，已发出的指令和用户副本仍按界面说明处理。

## 3. 范围与优先级

| 能力 | P0 必须交付 | P1 候选 | P2 独立立项 |
| --- | --- | --- | --- |
| 插件管理 | 本地 JSON 导入、校验、列表、详情、启停、替换、回退、卸载 | 目录包、导出、开发模式重载 | 在线市场、签名发布、自动更新 |
| 内容扩展 | Prompt、Recipe、打开模板的快捷动作 | 主题、类型化设置、项目启用范围 | 自定义界面面板 |
| 运行扩展 | 手动预览确认后进入现有队列 | 更丰富的宿主声明式动作 | JS/WASM 运行时、事件自动化、第三方 Agent |
| 诊断 | 最近管理操作和可读错误 | 诊断导出、作者校验工具 | 集中观测、远程管理 |

不在 P0：安装脚本、任意 Shell 命令、Node/npm 执行、HTTP 请求、文件读写 API、
凭证读取、Provider 配置改写、跨项目自动派活、Agent 自动启动、自动后台触发、
替用户处理终端权限框、自动完成判断、云账号和市场。

## 4. 信息架构

主入口为“设置 → 插件”，复用设置左导航和现有亮暗主题。
Quick Open 增加宿主动作“管理插件”；不新增抢占 Agent 的全局快捷键。
Recipe 面板增加“我的 Recipe / 插件模板”分组，插件模板按插件归属展示。
插件详细信息留在设置；日常运行表单只展示来源、目标、变量、预览和投递状态。

设置页从上到下：标题与说明、导入按钮、搜索框与状态筛选、插件列表。
每行显示名称、作者（标注作者自述）、版本、简述、状态、模板/动作数量、启用开关、详情入口。
初始排序按显示名称，再按插件 ID，确保同名顺序稳定；搜索匹配名称、ID、作者与描述。
筛选：全部、已启用、已禁用、有问题。P0 上限为 50 个已安装插件。

详情页展示：名称、ID、版本、作者、来源文件名、安装/更新时间、兼容范围、
状态原因、模板清单、完整模板文本、动作目标、最近诊断、更新/回退/卸载按钮。
普通视图不显示完整用户磁盘路径；技术诊断按需展开且不含 Prompt 变量值。
README 类富文本、远程图片、外部链接和 HTML 渲染不在 P0。

## 5. 导入与安装

F-01：点击“从文件安装”，系统文件选择器筛选 JSON；取消不报错、不改变列表。
F-02：读入后先校验，再显示安装预览；校验通过不代表已安装。
F-03：预览至少包含身份、版本、作者自述、能力说明、模板原文、动作列表、兼容结果。
固定说明：“模板会在你确认发送后交给所选 Agent；其执行权限由 Agent 自身控制。”
F-04：点击“安装”后保存宿主管理的快照，不依赖源文件继续存在。
F-05：安装成功状态为“已禁用”，显示“启用”主按钮；安装不发送 Prompt。
F-06：取消预览不产生安装记录；落盘失败显示原因和重试入口，不能假装安装成功。
F-07：导入同 ID、同版本时拒绝覆盖，提示作者递增版本；不以不同文件名当新插件。
F-08：同 ID 不同版本进入版本替换流程；不同 ID 即使名称相同也可安装，界面显示 ID 区分。
F-09：不兼容或不支持的能力在预览阶段拒绝安装，显示具体字段和支持范围。

安装检查顺序：文件大小 → UTF-8/JSON → manifest/schema → 唯一性/引用完整性 →
插件 API 与宿主版本 → 总容量 → 已安装身份冲突 → 预览确认 → 持久化 → 列表刷新。
任何失败不应注册一部分模板。

## 6. 启用、禁用与故障恢复

F-10：启用时重新检查完整性与兼容性；所有贡献一起生效，部分失败则整体不启用。
F-11：禁用使 Quick Open 动作与模板入口立即不可运行；已打开预览的确认按钮同步失效。
F-12：若有此插件运行中的轮次，禁用对话框显示待发数量，并说明将中止尚未发送的步骤。
用户确认后调用既有 removeRun/abortRun 语义，清掉待发与重挂回滚记录，再关闭入口。
已经交给终端的内容无法撤回，不发送 Ctrl+C，不关闭目标会话。
F-13：禁用或卸载不影响其他插件、手工 Prompt 和独立复制的 Recipe。
F-14：故障插件显示“不可用 + 原因”；宿主继续启动，用户可查看详情或重试。
根库可安全写入时允许卸载；库损坏或只读故障时只允许诊断和重新读取，避免覆盖原件。
F-15：重启只恢复安装与启停配置，不自动重放上次 Prompt 或 Recipe 运行。
F-16：应用升级后发现不兼容，则该插件不可用；不自动降级宿主，也不删除插件数据。

## 7. 使用 Prompt 与 Recipe

F-17：选择模板后统一打开宿主运行预览。Prompt 视作单步骤模板，Recipe 为多步骤模板。
F-18：目标列表仅为当前项目中支持 Prompt 的 Codex/Claude 会话；Shell、SSH 不作为目标。
无当前项目时先提示选择项目；无目标时提示从侧栏创建 Agent 会话，不代为启动。
F-19：优先选当前活动且符合条件的会话；不符合时保持未选，不能默默发给另一会话。
F-20：目标显示项目、会话名称/标题、Agent 类型与活动状态；退出/错误状态不可提交。
忙碌或等待确认允许入队，文案分别为“加入队列”“等待 Agent 确认后发送”。
F-21：变量沿用 `{{name}}`，按首次出现顺序生成输入框；空白值阻止提交。
不支持表达式求值、Shell 插值、环境变量注入、自动读取剪贴板/项目文件。
变量替换一次完成，不递归解释用户输入中的占位符；变量内容不持久化。
F-22：提交前展示替换后的完整文本、步骤数、插件与版本、目标会话；用户可取消。
P0 模板原文只读；要修改原文先“复制为我的 Recipe”。
F-23：提交瞬间重新检查启用状态、版本修订号、目标存活与项目归属。
预览后插件被更新/禁用、项目切换、目标退出时阻止提交并提示重新选择。
F-24：点击一次只创建一轮；按钮有提交中状态，快速双击不得重复入队。
步骤进入同一个既有 Prompt 队列，不新增并行发送器，不绕过 awaiting-choice。
F-25：运行视图沿用“待发送 / 已送达 / 已跳过 / 已中止 / 等待确认”。
所有步骤发完显示“已全部送达”，附“Agent 执行结果请查看会话”，不显示“任务成功”。
F-26：重试/跳过/中止复用 Recipe 行为；重复执行必须是新的用户动作。
插件失效后的历史轮次可查看，但禁止重发；重启不恢复这些内存运行记录。

## 8. 快捷动作与用户副本

F-27：动作只允许打开该插件声明的模板预览，不允许声明终端命令或直接发送。
F-28：Quick Open 展示动作名称与“插件名 · 版本”，搜索可命中插件名和关键词。
内部 ID 使用宿主插件命名空间；同名不得覆盖内置动作或其他插件动作。
F-29：未启用、故障、不兼容插件的动作不出现在搜索结果中。
F-30：“复制为我的 Recipe”产生独立 ID 和步骤 ID，明确显示“副本不随插件更新”。
模板来源属于只读插件目录，不写入现有 `belfry.recipes.v1`；只有用户副本进入该存储。
复制前检查现有 40 条上限；满额时阻止操作并提示整理，不能静默挤掉旧内容。
插件卸载、回退或更新均不改用户副本。用户自己管理副本名称与删除。

## 9. 更新、回退、卸载

F-31：P0 为手动导入替换；不联网检查版本、不静默更新。
替换预览显示旧/新版本和新增、删除、变更模板/动作；降版本用明确的“降级”措辞。
F-32：存在待发/可重试轮次时，说明替换将中止旧版本轮次；确认后先中止再换版本。
替换成功一律禁用，用户审阅后重新启用；不自动改变已发文本。
F-33：校验或原子替换前失败时保持原版本和原启停状态；原子替换后失败必须读回，
无法确认时显示结果未知并暂停插件使用，详见第二阶段设计；已中止运行不自动重启。
F-34：保留最近一次替换前的有效版本快照；回退也先确认并中止运行，恢复后默认禁用。
回退成功清空回退槽；新一次替换重新创建回退槽，避免暗含多版本历史管理。
F-35：卸载确认说明会删除插件定义、上一版本和管理记录，并中止其待发步骤；
同时说明用户 Recipe 副本保留、已发 Prompt 无法撤回。确认后执行，失败可重试。
F-36：P0 无插件私有数据，所以没有“保留插件数据”选项；卸载不删除源文件、项目文件或用户副本。

## 10. 状态与界面细节

稳定状态：已禁用、已启用、不可用。操作状态：校验中、安装中、切换中、替换中、卸载中。
兼容失败、文件损坏、存储异常是不可用原因，不是“已启用但什么也不做”。
操作期间禁用重复提交；不让全应用不可交互。切换设置分类按现有 guarded 模式保护确认流程。
空列表：说明本地安装方式，并提供导入按钮；无搜索结果可清空筛选；错误可重试。
长名称截断有 tooltip，详情可看完整；文本作为纯文本，不执行 HTML/Markdown 内嵌内容。
支持 720×480 最小窗口：列表允许纵向滚动，详情与预览切换为单列，按钮始终可达。
支持键盘 Tab、Enter/Space、Escape，弹窗焦点限制与关闭后焦点返回；
状态同时提供文字，不能只依赖颜色；亮暗主题保持现有字体与配色规范。

多实例推荐限制（待用户确认）：插件功能只在取得占用权的一个应用实例中可用。
其他实例显示“插件正在另一个 Belfry 窗口中使用”，提供“重试”，不暴露可运行的旧入口。
不阻断 Shell、Agent 或普通 Recipe。占用实例退出后，点击重试重新加载插件状态；
不自动接管，不恢复旧运行。不能取得占用权时保留提示；磁盘权限错误需区别于正常占用。

## 11. 性能、可靠性与兼容

P0 限额详见技术设计；越界明确拒绝，不截断成另一份插件。
50 个插件下管理列表交互与 Quick Open 索引构建目标各低于 100ms，需记录设备与样本；
1MiB 文件校验目标低于 500ms（不计系统选择器与用户审阅），不达标需报告实测瓶颈。
这些是验收目标，不是当前已测结果；磁盘操作异步处理，不阻塞终端键盘输入。
兼容 macOS 14+、Windows 10 22H2/11；路径使用平台 API，测试中文、空格与长路径错误提示。
插件存储不可读时仍可启动终端；不以空列表静默覆盖损坏文件。

## 12. 后续演进条件

P1：目录包与静态资源需先定义路径约束、大小上限、符号链接策略和包摘要；
项目范围需先定义稳定项目身份、移动目录规则、启用优先级与跨项目检查。
P2：执行代码需单独设计隔离进程/沙箱、宿主 capability broker、超时与资源限制、
撤销权限、故障熔断和 CSP。当前 Tauri 主窗口能力不能直接授予第三方插件。
第三方 Agent 涉及 AgentKind 与工作区/历史/resume 契约，应独立迁移计划与兼容测试。
市场需要发布者身份、签名/来源校验、版本撤回与更新策略，不能用本地作者字段替代可信身份。

## 13. 需求假设与决策权

当前按“模板与快捷动作优先”设计，用户可将首期重定向到面板或 Agent 扩展。
一旦重定向，应先更新本设计与开发任务，避免边写边加入执行环境。
本设计给出可评审协议草案，不等于用户已确认修改共享类型、持久化和根配置。
开发可先完成独立模块与验证；触及用户全局规则中的确认项，提交具体差异与理由后再实施。
