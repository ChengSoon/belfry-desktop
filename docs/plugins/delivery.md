# 开发任务包与验收标准

## 1. 交付边界

项目经理拥有本设计包，开发拥有功能实现、实现说明与验证证据。
首期交付仅为 requirements.md 中 P0；P1/P2 不顺手实现。
协议与恢复细节补充见 [第二阶段详细设计](./phase-two-design.md)，其 AC-33–40 纳入后续验收。
本次设计文档不会自动授权根配置、依赖、shared contract/schema/shared types、
持久化、数据库、Git 历史/远程或删除操作。遵循用户提供的 AGENTS 确认门禁。
开发须先提出具体受影响文件、最小差异、理由、兼容影响、测试与回退方案，
由项目经理汇总给用户确认；此前可做独立非持久化模块与测试。
不得以“做插件必须如此”为由直接改现有共享类型或根入口。

## 2. 工作分解与顺序

| 任务 | 交付 | 依赖 | 验证 |
| --- | --- | --- | --- |
| D0 可行性 | 接入点、门禁文件、实现顺序、风险与工作量估算 | 当前源码 | 逐文件依据；特别核对多实例与队列归属 |
| D1 纯领域模块 | 插件私有契约、校验、兼容、目录/动作命名、版本差异 | D0、设计基线 | 合法/非法固定样例，边界单测 |
| D2 存储 | 有界读取、安装/替换/回退、revision、恢复 | D1，持久化边界批准 | Rust 文件故障、竞争、损坏测试 |
| D3 管理界面 | 列表、详情、预览、启停、替换、卸载、诊断 | D1；可先 mock D2 | 空态、错误、键盘、亮暗、小窗口 |
| D4 模板运行桥接 | 变量预览、目标确认、runId 来源、中止 | D1、目录接口 | 忙碌、权限等待、重挂、禁用竞态 |
| D5 宿主接入 | 设置、Quick Open、Recipe、Tauri 命令注册 | D2–D4，相关边界批准 | 核心回归与完整桌面冒烟 |
| D6 作者示例/文档 | 一个有效示例包、格式说明、用户操作说明 | 定稿协议 | 示例走真实安装/运行流程 |
| D7 验收 | 测试结果、平台证据、未解决问题、变更清单 | D5、D6 | 下列 AC 全部可追溯 |

D1 中新增共享前后端协议文件前先明确其是否属于用户的 shared contract 门禁；
未获批准可编写纯函数原型和私有测试夹具，不声称协议已冻结。
D2/D4 为高价值行为与状态变更，先测试后实现；D3 样式不机械补镜像测试。
只有一个开发会话时按上述依赖串行；不要创建另一个“开发”子代理代替真实会话。

## 3. 文件归属建议

主要新增：`src/plugins/**`、`src-tauri/src/plugins/**`、`examples/plugins/**`。
本设计包 `docs/plugins/**` 由项目经理维护；开发反馈通过 Belfry 返回，不直接覆盖。
必要局部接入候选：`src/settings/SettingsPanel.tsx`、`src/quickopen/items.ts`、
`src/quickopen/useQuickOpen.ts`、`src/recipe/RecipePanel.tsx`、`src/components/AppOverlays.tsx`。
总入口候选：`src/App.tsx`、`src/components/Workbench.tsx`、`src-tauri/src/lib.rs`。
上述仅为候选，开发基于真实依赖给出最小集合；不能先把它们全部重构。

默认保持：AgentKind、WorkspaceTab、PromptOrigin、用户 Recipe schema、Provider、
协作协议、终端 PTY、现有快捷键体系、根构建与发布设置。
依赖如确有必要，先说明现有工具为何不足，不能为 SemVer 三元组/JSON 导入引入整套插件框架。
函数 ≤ 50 行、文件 ≤ 300 行、嵌套 ≤ 3、位置参数 ≤ 3、复杂度 ≤ 10；
现有超限文件只做最小接线，拆分新逻辑，不借任务重构整文件。

## 4. 验收矩阵

| ID | 场景 | 必须看到的结果 |
| --- | --- | --- |
| AC-01 | 全新用户打开插件设置 | 空态可导入，Shell 正常，未创建无关配置 |
| AC-02 | 导入有效示例并取消 | 预览准确，安装列表与磁盘状态不变 |
| AC-03 | 安装有效示例 | 默认禁用，不执行代码、不发 Prompt，源文件移走后仍存在 |
| AC-04 | 启用再重启 | 状态保持、模板与动作恢复，无旧运行自动重放 |
| AC-05 | 非 JSON/错误 UTF-8/重复键/未知字段 | 有具体错误，零部分注册，无覆盖 |
| AC-06 | schema/API/宿主版本不兼容 | 指明需要的版本与当前版本，拒绝导入或禁用旧插件 |
| AC-07 | 重复模板/步骤/动作 ID、悬空引用 | 精确字段错误，原插件仍可使用 |
| AC-08 | 超大文件/文本/过深 JSON/第 51 个插件 | 明确配额拒绝，不截断、不阻塞终端 |
| AC-09 | 元数据 HTML、终端 ESC、NUL、双向控制字符 | 纯文本呈现或按协议拒绝/提示，无代码/控制序列执行 |
| AC-10 | Quick Open 搜索同名动作 | 来源可区分，内置动作不覆盖，仅启用插件可见 |
| AC-11 | 无项目/无 Agent/Shell/SSH | 不可误发，明确下一步选择路径 |
| AC-12 | 变量缺失、纯空白、替换值含占位符 | 缺失阻止，替换不递归；最终字节配额生效 |
| AC-13 | 空闲 Agent 提交一次及双击 | 一轮入队，目标固定，无重复投递 |
| AC-14 | talking/awaiting-choice 时运行 | 保留排队，不代答确认，空闲后按原顺序发送 |
| AC-15 | 预览后目标退出/项目切换/插件替换 | 拒绝陈旧提交，不转发到别的会话 |
| AC-16 | 所有步骤投递 | 显示已全部送达，不显示任务执行成功 |
| AC-17 | 待发/已送/in-flight 时禁用 | 仅撤销所属待发和重挂记录，已发不强行中断 |
| AC-18 | 运行超过可见历史条数后禁用 | 被 UI 淘汰轮次的待发步骤仍能正确撤销 |
| AC-19 | 手工 Prompt/其他插件并存时禁用 | 其他来源队列、终端与用户副本不受影响 |
| AC-20 | 复制模板及达到 40 条 Recipe 上限 | 新 ID 独立副本；上限阻止且无旧内容被挤掉 |
| AC-21 | 同版本/新版本/旧版本导入 | 同版本拒绝；替换有差异预览，降级有明确措辞 |
| AC-22 | 替换后回退 | 旧版本可恢复，默认禁用，回退槽规则一致 |
| AC-23 | 保存中断/权限失败/存储写满 | 不报成功，旧存储有效；已中止运行不会偷偷恢复 |
| AC-24 | 损坏 registry 或坏 entry | 原件保留，不空写覆盖，Shell 可用，有恢复提示 |
| AC-25 | 并发操作及陈旧 revision | 一个有序结果或 STATE_CONFLICT，无丢更新 |
| AC-26 | 双进程同时启动、退出/崩溃后接管 | 仅一个插件 owner；非 owner 管理/运行/重试入口受控，Shell 正常；显式夺锁后重读且不重放；PTY 子进程不得延长锁寿命 |
| AC-27 | 卸载取消/确认/失败重试 | 取消不变，确认仅删受管记录，用户文件和副本保留 |
| AC-28 | 中文/空格路径与 Windows 错误路径 | 正常可读或可解释报错，不拼接 shell |
| AC-29 | 亮暗主题、720×480、键盘 | 可滚动、焦点正确、按钮可达、文字表达状态 |
| AC-30 | 原有核心功能回归 | Shell、Agent、Prompt/Recipe、Quick Open、协作功能无新增失败 |
| AC-31 | 50 插件性能样本 | 记录设备、包规模、耗时，达到目标或明确列为未满足 |
| AC-32 | 诊断与存储抽查 | 不含变量值、渲染 Prompt、凭证或无必要的完整路径 |

## 5. 测试与完成门禁

定向单测：manifest/版本/目录/状态转换/来源关联/预览失效；Rust 存储故障与竞争。
集成测试：安装到 Quick Open/Recipe 的完整目录流；运行到已有队列；禁用到 removeRun。
桌面冒烟：macOS 与 Windows 至少各一次真实安装、启用、发送、替换、回退、卸载。
只有一个平台环境时，另一个明确标记“未验证”，不得用跨编译替代 GUI/路径验证。

仓库规定最终检查：`pnpm test`、`pnpm build`、`cargo test`（在 `src-tauri` 执行）。
测试前记录基线；已有未提交改动导致失败时注明归属与证据，不擅自修无关功能。
存储落盘使用临时目录与 mock 目标；不要让测试修改真实用户插件或 Agent 配置。
完成前做代码 review，重点是容量、状态竞态、原子失败、队列撤销与 UI 来源一致性。
无可用 reviewer 会话时，开发提供结构化自审，项目经理核对需求映射；不假称独立 review 已完成。

## 6. 开发回报格式

1. 已实现的 D/AC 编号，未实现或偏离项及原因。
2. 修改文件与授权边界；有无触碰开始时其他工作的未提交文件。
3. 实际命令、退出码、关键输出；失败与未运行项明确区分。
4. macOS/Windows 验证证据、截图/记录路径和环境。
5. 已知限制、剩余风险、下一步建议；不承诺未经验证的发布就绪。
6. 最后执行 `belfry done <任务号> <简要结果>`；无法继续则 fail 并说明真实阻塞。

送出任务不等于开工；只有 done 才是该任务的完成信号。
Git commit/push/PR/发布不在本次实现授权内。
