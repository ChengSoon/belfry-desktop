# 房间流程图的节点测量

成员活动变化时，`RoomFlow` 会重建传给 React Flow 的受控节点。此前这些节点没有携带
`measured`，也没有接收 `onNodesChange` 的尺寸通知。当前锁定的 React Flow 12.12.1 /
xyflow system 0.0.84 会把这种节点当成需要重新初始化的节点，清空尺寸及 `handleBounds`。

在受控时序中，真实 ResizeObserver 回调先测得尺寸，下一批活动节点紧接着覆盖它们。
节点组件未渲染过中间的“已初始化”状态，其观察 effect 的条件仍是未初始化；同一个 DOM
节点没有再次订阅，布局尺寸又没有改变，于是五个节点持续 `visibility:hidden`，连线无法生成。
DOM 仍有 232×64 的尺寸，成员文本也已更新。这解释了为何只检查容器或状态文本不能发现问题。

修复在 `RoomFlow.tsx` 中接收真实的 dimensions 通知，按节点 id 保留尺寸，移除离开的节点记录。
仅更新活动、文本或语言时把这些尺寸带回受控节点，保留现有连接点信息。若首次测量与待处理的
节点更新交错，导致连接点仍未初始化，则在尺寸进入受控节点之后通过 `useUpdateNodeInternals`
重新读取当前 DOM。没有预填常量尺寸、强制可见性或更改 CSS/动画。

尺寸实际改变时仍接受后续测量。切房会随原有 RoomView 生命周期卸载画布，新的房间重新测量。
活动变化保持用户缩放；成员集合或画布尺寸变化仍按原逻辑适配视野，包括顶部选择卡片出现时。

## 验证

新增 `src/components/lazy/testing/rooms-flow-measurement.case.mjs` 覆盖：

- 首次真实测量恰好在下一批活动节点采纳前交付，最终五节点可见、四条连线、精确一条动画边。
- 暗、亮主题下连续活动和语言更新不隐藏或替换已测量节点；画布尺寸不变时保持用户缩放。
- DOM 从 232×64 改为 280×80 后，连线端点继续贴合真实连接点；后续活动更新保留新测量。
- 成员退出、重新加入和切换房间后，节点/连线数量正确，并重新测量新 DOM。

调度用例只在自己的浏览器中包装真实 ResizeObserver 回调和节点采纳入口。定位 provider 使用
测试中的 React fiber；找不到时会明确失败。它不进入产品代码，不伪造尺寸，也不改变原房间用例
的时序或断言。原精确动画边数、真实动画推进/停止及 reduced-motion 回归保持原样。

```sh
node --test --test-concurrency=1 src/components/lazy/testing/rooms-*.case.mjs
pnpm test src/rooms
pnpm build
```

本地独立分支的房间浏览器验证 27/27（23 项既有、4 项新增），房间单测 64/64，构建及词条
检查通过。将相同修复应用到精确 `af64306` 的临时副本后，相关流程浏览器验证 8/8；其中保留
原暗亮活动测试的精确动画边数、真实动画推进/停止及 reduced-motion 断言。上述运行均零跳过。

旧实现 `af64306330ddba5bf902d1e3ac7b2a9c3f4c1733` 在同一新增调度用例中超时，暗亮连续
可见性用例也失败；尺寸和成员生命周期对照通过。仅回存尺寸、未恢复连接点的中间实现仍在
调度用例中失败，表明只让节点出现不能保证连线恢复。

T32 CI 42656249993 的 macOS 失败产物与同树 PR 42656263650 的成功产物并列保留。
本地 CPU×8 的 12 轮自然活动切换未复现持续空白；上述调度是有控制的因果验证，尚未还原
该次 CI 的自然回调顺序。ResizeObserver 通知本身不作为根因证据。
