# 开发1：用量统计增量与取消

## 目标

直接实现优化并完成定向测试。当前用量面板每次 `usage_analytics` 都完整重扫两家 CLI 日志；
`src/usage/insights/requests.ts` 的 cancel 只忽略响应。基线本机 debug 扫描 247 文件需 8.50 秒。
需要减少重复 IO/解析，并在面板关闭或查询替换后停止无用后台工作。

## 所有权

- scope_write：`src-tauri/src/usage/**`、`src/usage/insights/**`；
  本目录 `developer-1-result.md`、`developer-1-integration.md` 与必要的本任务性能证据。
- scope_read：全仓库，尤其 history/search 的取消机制、usage/session 的增量读取与现有 analytics 测试。
- 禁止编辑 `src-tauri/src/lib.rs`、`src/terminal/**`、workspace、根配置/锁文件、其他开发的文件。
- 需要根入口注册时，尽早写 `developer-1-integration.md`，给出完整 state 路径和 command 路径、参数。
  项目经理负责根入口接线，你负责模块 export 和内部实现。

## 实现要求

1. 建立有界缓存；未变化日志重复查询不重新解析，续写尽可能只消费新增内容。
2. 查询窗口/项目变化复用扫描结果，但必须保持 Codex 累计基线、resume 分片、Claude 重复消息、
   流式修正、未知日期、账号额度及四类 Token 的现有统计语义，不能简单按 mtime 丢掉历史基线。
3. 文件截断、替换、删除与读取失败正确失效；坏行/超大行保持有界读取和明确诊断。
4. 实现真实后台取消；替换请求、关闭面板停止旧工作；取消一位消费者不得取消其他有效消费者。
   相同查询并发不重复做全量扫描。等待缓存锁也应可取消，不能排队执行大量过时任务。
5. 前端保留旧响应/错误隔离，增加实际取消 IPC。现有 query/report 字段语义保持兼容。
6. 取消/缓存结构有上限和清理，未完成扫描不能污染已完成缓存。
7. 避免新依赖和持久化/schema 变更。尽量新增职责单一模块，修改后的生产文件不超过 300 行。

## 可验收证据

- 原有 analytics / session / scan 测试通过，补有价值的回归：并发合并、真实取消、取消隔离、
  冷热查询结果一致、追加/替换/截断/删除、resume 与重复消息不重复计数。
- 用计数或实际读取量证明：未变化文件热查询不重读正文；追加后只读新增范围或说明必要回退。
- 在同一构建模式下报告冷/热耗时和查询规模，不以 release 对 debug 的差异充当收益。
- 不输出用户日志正文、凭据或个人提示词；优先可复现的临时日志，真实日志只读且只报汇总指标。
- 前端定向测试和类型检查，注明全量测试若受其他开发在途代码影响的具体错误。
