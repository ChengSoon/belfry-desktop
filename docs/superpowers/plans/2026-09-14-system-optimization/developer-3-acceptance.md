## Hook 与统计的原生步骤

1. 仅使用本任务新建的独立 QA 身份和临时 CLI 配置，按既有模拟模型 helper 准备 Codex/Claude；不操作正式 Belfry 会话。
2. 在 Codex 自身的 `/hooks` 界面审阅 QA Hook；不直接改写信任记录，也不把“已写入配置”当成“CLI 已信任并执行”。
3. 并行启动两条 Agent 会话，逐一触发输出、等待输入、等待许可、完成与退出，检查状态来源、标题和通知对象。
4. 切换活动会话及命名工作区，验证当前会话统计只使用自身的 Agent/sessionRef，持续追加日志后增量更新。
5. 同时打开聚合用量并切换窗口/项目过滤，检查与当前会话统计口径一致；取消、关闭重开、续写/轮转后的结果由开发1的定向证据与整合验证共同确认。
6. 保存截图、CLI/日志身份、追加前后计数和原日志 SHA256。完成后只清理经核对属于这次 QA 的临时进程与配置。

## Worktree 的原生步骤

1. 新建专用临时 Git 仓库；重建后的独立 QA 回读非法分支提示，不触碰用户正式仓库或既有任务 A 现场。
2. 创建 A/B 两个任务，分别打开 Shell/Agent；用文件与 Git 面板确认目录、分支、改动及会话互相隔离。
3. 在一个任务中准备改动，核对提交预览与实际状态；预览后再改动，确认过期票据被拒绝。
4. 将已提交任务合并到干净目标；验证脏目标被拦截。制造可控冲突并确认保留工作树、分支与改动。
5. 让工作树内的任务在后台继续运行且不 attach UI，确认清理仍因占用被拦截。
6. 显式结束 QA 任务后清理已登记工作树；检查未合并/忽略文件保护、不强制删除、保留分支。

## Windows 的原生步骤

1. 首次远程运行新的 PR 检查：MSVC/Windows SDK、真实 CLI sidecar、完整 Rust workspace、前端与强制浏览器回归。保存 runner URL 与实际结果。
2. 在 Windows 10 22H2 / Windows 11 验证 Shell Profile、ConPTY 输出/输入、OSC 10/11、中文与 emoji、调整窗口与分屏。
3. QA 中保留任务退出再打开，核对同一 worker PID、计数与滚屏、启动命令只执行一次；测试显式结束与缺失后台任务提示。
4. 检查自绘标题栏、最小化/最大化/关闭、文件窗口、剪贴板、凭据管理器与快捷键焦点，不用 macOS Chromium 结果替代 WebView2 证据。
5. 验证 NSIS 新装、升级、卸载与 OpenConsole 文件锁处理；`test-windows-installer.ps1` 只覆盖脚本的受控测试场景，不能替代安装包实测。
6. 发布先在草稿中检查两个 macOS 目标与 Windows 的安装包、签名及 `latest.json`；正式发布只由授权的远程流程执行。本任务未推 tag、触发 workflow 或发布。

## 插件与面板的验证边界

- 新 CI 强制存在 Chrome/Chromium/Edge，`BELFRY_REQUIRE_BROWSER_TESTS=1`；Node 运行器拒绝必跑集合中的跳过项。
- 未提供固定 PI 源码与 `market-fixtures` 时，4 项原版 Browser/Git Lens/Log Viewer/Todo 互操作明确列为独立验收，不伪装成通过。
- 本轮发现的旧 dropdown fixture/断言已由项目经理统一修正，最终必跑 Node 回归通过；过程与证据见 [开发3结果](developer-3-result.md)，没有禁用检查。
- 7 项开发服务器面板用例覆盖打开/关闭/加载失败/重试、尺寸、CSS 顺序、焦点返回与常驻兄弟组件保持挂载。
- 4 项生产面板用例直接服务完整 dist，仅模拟原生 IPC，覆盖真实 JS/CSS HTTP 503、Vite 预加载缓存、CSS 多次失败、静态共享依赖失败及新文档恢复；真实 App/xterm 节点与会话保持不变。
- 静态共享依赖在同一文档中无法恢复时，面板在一次局部重试后保留失败状态并取消无效重试，提供“返回终端”与保存工作后手动重开的说明；不自动重载全应用。浏览器新文档可恢复不等同于原生退出/daemon 重连已验收。
- 工作区浏览器回归使用真实 React Hook 和模拟 IPC，覆盖 StrictMode 首启一次、daemon 身份恢复、无启动命令重放、命名工作区焦点、过期请求隔离、持久化失败重试与批量历史恢复。
- 上述浏览器用例不证明真实 PTY/ConPTY 行为；原生后台任务与 Hook 仍按前述步骤收尾。
