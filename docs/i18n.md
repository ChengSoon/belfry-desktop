# Belfry 国际化约定

语言：`zh-CN`、`en`。用户偏好另有 `system`（跟随系统），默认跟随系统；系统语言以 `zh` 开头使用中文，其余使用英文。前端把偏好写入 localStorage `belfry.locale.v1`，解析后的语言写入 `document.documentElement.lang`，切换立即生效。

词条位于 `src/i18n/locales/{zh-CN,en}/<模块>.json`，key 使用 `<模块>.<组件或用途>.<语义>`。迁移存量文案使用 `<模块>.<文件>.text_<源文摘要>`，摘要保持稳定、不按行号编号；新增文案优先使用语义名。中英文 key 和插值参数必须一致。

组件调用 `const { t, locale } = useTranslation()`；组件外使用 `t()` 和 `getLocale()`。格式化示例：`t("rooms.pending", { count: 2 })`、`formatDateTime(date)`、`formatNumber(value)`、`formatCurrency(value, "USD")`。不要拼接翻译片段；整句使用 `{{name}}` 插值，React 负责转义显示。复数词条为 `{ "one": "{{count}} task", "other": "{{count}} tasks" }`，按 `Intl.PluralRules` 选择；中文通常只需 `other`。英文缺词回退中文；开发环境告警一次。

模块级的标签数组/对象不能在导入时把翻译结果冻结：在函数内构建，或使用 getter / `localized(() => value)` 按当前语言读取。带可见文案的 React 组件应订阅 `useTranslation()`；切换语言不重新挂载终端、丢失表单或清空草稿。

错误和操作提示也不能把当时的译文固定在 state 中。单条反馈使用 `useFeedback<string | null>(null)`，例如 `setError(() => errorMessage(cause))` 或 `setNotice(() => t("module.saved"))`；回调只做纯格式化，网络请求和写入仍在事件处理器中执行。同步校验可抛出 `new TranslationError(key, values)`，保留 key 和参数；复合状态保存 `AppFailure`，在渲染时读取 message。重连等机器判断读取原始错误码和诊断，不以译文判断成功或重试。

前后端同步接口约定：`app_set_locale({ locale: "zh-CN" | "en" }) -> Promise<void>`。应用启动、系统语言变化和用户切换时发送解析后的语言；后端用于通知、原生对话框、CLI 默认语言和 Agent 协作说明。CLI 的显式 `BELFRY_LANG` 优先于应用偏好。前端保留 `system` 的选择，后端接收实际语言。接口已由 T10 实现，后端行为和验证见 [backend-i18n.md](backend-i18n.md)。

后端面向用户的错误保留现有兼容字段，增加参数：`{ code: string, message: string, retryable: boolean, params?: Record<string, string | number> }`。`code` 使用稳定大写英文标识，语义不变时不改码；`message` 为可独立阅读的英文兜底。前端优先查找 `errors.<code>` 并插值 `params`，缺少对应词条时显示 `message`，不丢失诊断码。需要新错误码时同时提供英文含义、参数名和示例；不要把密钥、token 或完整配置放入参数。

后端错误码与具名参数统一从 [backend-error-codes.json](backend-error-codes.json) 同步；由 `scripts/export-backend-i18n.mjs` 从共享 Rust 词库导出。`fallbackOnly` 类别使用英文 message 兜底。共享目录还包含 CLI、通知及原生界面整句模板。

硬编码检查仅检查应用源代码中的可执行字符串/JSX 文本，不把注释、正则表达式、类型层字符串或测试夹具误报为界面词条。词典自身在 `src/i18n/locales`。T9 已清空基线；CI 拒绝再次加入白名单。真实用户内容、Agent 输出、标识符和协议语法保持原样，不翻译保存的数据。`rooms/recipientProtocol.json` 是固定收件人协议，`terminal/fontSample.json` 是字体覆盖检测样本，均不充当界面词条。

## 实现与验证

`src/i18n/core.ts` 负责词条展开、插值及复数；`store.ts` 保存偏好、监听系统语言与跨窗口存储变化。`index.ts` 提供翻译、React 订阅、延迟标签集合、Intl 格式化与结构化错误翻译。`main.tsx` 在挂载前初始化语言，并串行同步后端命令，避免迟到写入覆盖新语言。存储或同步不可用不会造成全局未处理异常。

`LanguageSettings` 使用 `components/controls/Select`，位于外观设置。插件中心原有三个 JSON 词库已并入模块词库，旧 `i18n.ts` 只保留兼容导出。

执行 `pnpm check:i18n` 检查硬编码、词条覆盖及参数一致性；CI 的 checks 工作流会执行。检查同时拒绝首尾空白、中文标点片段、`valueN` 参数，并检查静态 `t()` / `TranslationError` 调用是否提供必需插值和复数 count。`scripts/i18n-baseline.json` 当前必须为 `{}`。扫描器使用 TypeScript/JSX AST，不扫描注释和类型。

后端目录更新后运行 `pnpm sync:i18n`；CI 用 `node scripts/sync-backend-i18n.mjs --check` 检查生成文件与目录一致。前端同步 967 个错误/消息码，跳过 CLI 专用及 `fallbackOnly` 类别。日期、数字、货币和列表使用 `formatDateTime`、`formatNumber`、`formatCurrency`、`formatList`；传给复数的 count 使用原始数字，`t()` 会统一格式化数字参数。

T8 完成时已迁移 452 处源码字符串，包含外壳及其自定义控件；中英文各 645 个词条，基线剩余 1905 处由 T9 继续处理。`pnpm test` 的 179 个文件、1054 项测试通过，`pnpm build` 通过。`i18n.case.mjs` 的两项生产浏览器用例验证默认系统语言、即时切换、输入和终端实例保留、重启持久化、原生命令同步、系统语言变化以及 720×480 下的操作；T3 五项生产安全回归也通过。

## T9：全部界面迁移（2026-11-09）

rooms、collab、git、history、usage、provider、plugins、terminal、filepreview、quickopen、shortcuts、setup，以及工作区、Hook、诊断和外壳均已迁移。中英各 3,359 条，硬编码基线为零。原外壳迁移中的会话/字体/待确认数量、日期及范围限制已改为整句插值、复数或 Intl 日期，全部 `valueN` 参数已替换。插件标题、面板与运行上下文跟随应用语言，切换不重挂终端或插件 surface。

验证：185 个 Vitest 文件、1,096 项测试通过，生产构建与目录同步检查通过。12 项国际化浏览器用例覆盖设置与系统语言、失败面板重试、房间与历史、Git/Provider、插件市场、项目与 SSH、快捷键、环境与 Hook；包含 720×480 下的实际点击、未保存输入、现有错误、终端与插件身份保留。连同 T3/T15/T16 及房间可靠性回归，最终组合为 31 项全绿。浏览器证据使用真实生产资源和隔离 Chromium，原生 IPC 为可控夹具；不替代 Windows/WebView2 原生验证。

完整 CI 插件/浏览器入口也已运行，仓库自带 254 项必跑用例全部通过、零跳过；未配置 `BELFRY_PI_SOURCE` 的 4 项原版 PI 互操作用例不在该次运行范围。详细入口与日志见 [frontend-reliability.md](frontend-reliability.md)。新增 `*.case.mjs` 自动进入 CI 插件/浏览器套件，后端 Node 词库用例由单独的 `node --test` 步骤执行。
