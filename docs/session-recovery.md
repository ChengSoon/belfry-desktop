# 退出与会话恢复

## 正常退出

退出弹窗只有「确认退出」和「取消」。确认退出默认保留后台任务，关闭应用内的输出连接，不关闭后台 PTY。取消、Esc 和弹窗关闭按钮都只取消退出。

旧 UI 的 `retain` 请求仍兼容；退出接口不再接受 `terminate`。需要停止任务时，应明确关闭对应会话，不把结束任务混入退出确认。

## 再次进入

1. 优先按保存的后台任务 ID 连接原 PTY，恢复缓冲输出，不重启进程。
2. 旧 ID 找不到时，尝试查找同一标签的现存后台任务，并继续校验项目、类型和标签，避免重复启动或误连其他项目。
3. 恢复已保存的会话或重连时，后台记录仍在但进程已退出，也会自动建立替代进程。只回放旧终端输出的普通请求保持原来的行为；`recoverExited` 必须明确开启。替代进程只启动一次，启动后立即退出不会循环重启。
4. 后台明确返回 `SESSION_MISSING` 时，清除失效 ID，自动恢复一次。有原生会话 ID 的 Agent 使用最新的 resume 身份；无历史身份的 Shell／SSH／Agent 重新建立会话，并提示恢复方式。
5. 输出连接中断时，按 0.5、1、2 秒最多自动重连三次，每次仍携带原 PTY ID。连接持续稳定十秒后才重置重试次数；卸载、关闭或手动重启会取消等待中的重连。超过次数后保留错误和手动重连入口。
6. 恢复和手动重启都不会重放旧输入，也不会再次执行项目启动脚本。网络错误只允许重试接驳；权限、项目不匹配和协议错误不触发新进程。

后台协议保留结构化错误码及 retryable；旧后台仅返回字符串时，兼容识别旧的「原后台任务已不存在」错误，不再将其误当成可以不断重连的普通 IO 错误。

应用通过后台能力声明选择恢复方式。新后台在目标校验后原子替换已退出的记录；旧后台在成功校验并确认退出后，只关闭那一个 PTY ID，再创建一次。升级应用不要求关闭其他后台任务。

## 原生会话身份

原生会话 ID 独立于 Hook 状态保存。Hook、已认证 Codex MCP 请求的 `threadId`、Claude 启动时确定的会话 ID 都可补充身份；身份变化只更新恢复引用，不重新挂载正在运行的终端。手动重启使用运行中捕获的最新身份，重新打开应用则从工作区存档恢复这一身份。

本地 Codex 未启用 Hook、也还没有调用 MCP 工具时，会尝试从 Shell 快照读取字面量 `BELFRY_TAB_ID`，再核对历史记录中的项目和 CLI 主会话来源。只有精确匹配当前标签的唯一候选才会用于恢复；多个候选、记录不完整或超出读取上限时不猜测。快照不会作为脚本执行，环境变量正文不会写入事件或存档。新会话会在身份出现后补存。

## 验证与边界

本地回归包含已退出记录的恢复、旧后台兼容、身份入档与重启参数、有限重连、卸载时的迟到响应、项目隔离及启动脚本不重放。生产构建的真实浏览器回归验证身份更新不重挂终端、自动重连、重开文档读取存档、点击重启续接最新历史及恢复后的键盘输入；恢复按钮位于 xterm 画布之上，可以正常点击。

macOS 的 `scripts/test-terminal-daemon.py` 使用临时 daemon，强杀独立客户端后原 PTY 与 PID 保持不变；强杀测试 Shell 后只重建一次，能继续接收输入，也不重发启动命令。`scripts/test-terminal-daemon-recovery.py` 使用真实 Codex CLI 和本机模拟模型，强杀 CLI 后验证原生 ID 保持一致、原用户消息和回复重新呈现，模型请求数量不增加。`scripts/test-terminal-daemon-agents.py` 同时验证 Claude Hook 与 Codex 未审阅 Hook 回退，以及普通退出回放的兼容性。这些脚本只使用独立临时配置和测试进程。

系统重启、手动杀死后台或后台崩溃后，原进程的运行内存不能恢复；只能续接可用的 Agent 历史或重新建立会话，不能声称原任务仍在执行。历史身份从未保存且无法核验时，需要从历史记录中选择原对话。Agent 历史不可用时会保留 CLI 的错误，不偷偷重发任务。Windows 整机运行验收需在 Windows 环境执行。
