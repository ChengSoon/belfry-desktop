# 退出与会话恢复

## 正常退出

退出弹窗只有「确认退出」和「取消」。确认退出默认保留后台任务，关闭应用内的输出连接，不关闭后台 PTY。取消、Esc 和弹窗关闭按钮都只取消退出。

旧 UI 的 `retain` 请求仍兼容；退出接口不再接受 `terminate`。需要停止任务时，应明确关闭对应会话，不把结束任务混入退出确认。

## 再次进入

1. 优先按保存的后台任务 ID 连接原 PTY，恢复缓冲输出，不重启进程。
2. 旧 ID 找不到时，尝试查找同一标签的现存后台任务，并继续校验项目、类型和标签，避免重复启动或误连其他项目。
3. 后台明确返回 `SESSION_MISSING` 时，清除失效 ID，自动恢复一次。有原生会话 ID 的 Agent 使用原有 resume 参数；无历史身份的 Shell／SSH／Agent 重新建立会话，并提示恢复方式。
4. 恢复时不会重放旧输入，也不会再次执行项目启动脚本。
5. 网络、权限、项目不匹配等错误不触发新进程。自动恢复再次失败时保留具体原因，不无限重试。

后台协议保留结构化错误码及 retryable；旧后台仅返回字符串时，兼容识别旧的「原后台任务已不存在」错误，不再将其误当成可以不断重连的普通 IO 错误。

## 验证与边界

本地回归包含退出按钮、退出策略、历史恢复参数、失效 ID 清理、恢复次数、卸载时的迟到响应、项目隔离及启动脚本不重放。真实 macOS 后台进程冒烟验证客户端退出后任务继续运行，重新连接和旧 ID 回退保持相同 PTY 与 PID。

系统重启、手动杀死后台或后台崩溃后，原进程的运行内存不能恢复；只能续接可用的 Agent 历史或重新建立会话，不能声称原任务仍在执行。Agent 历史不可用时会保留 CLI 的错误，不偷偷重发任务。Windows 整机运行验收需在 Windows 环境执行。
