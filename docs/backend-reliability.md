# 后端可靠性回归

2026-11-08 修复记录。这里记录故障条件与恢复语义，不把单元回归等同于 Windows 原生或断电验收。

## 插件与 CLI 边界（T6）

- 设置按最终缩进 JSON 的 UTF-8 字节限制为 1 MiB。单次补丁仍限制为 64 KiB。累计、中文、默认值和并发写入均计入最终限额；超限不替换旧文件。旧超额文件的错误给出原文件完整路径，可先复制导出，再精简到 1 MiB 内重新加载插件。应用不自动删减用户设置。
- 插件调用超时先 TERM，400 ms 后强杀整个进程组；取消给插件 400 ms 响应，仍无回执再进入 TERM/强杀流程。Windows 使用 taskkill /T，强杀阶段加 /F。Rust 宿主写入使用有界队列，截止时间覆盖排队、阻塞写入和响应；超时回收宿主，worker 的 IPC 断开也回收子孙进程。
- CLI 整次 IPC（包括兼容性探测）默认最多五秒；`wait --timeout` 使用更早的用户截止时间，响应最多 1 MiB，半帧不被当成有效操作。服务端最多 64 个在途连接，每个连接有五秒绝对 IO 截止时间。

T10 回归补强：CLI 截止时间从进入 `main` 开始，包含语言初始化；macOS 语言框架按需加载，避免新增的框架装载发生在计时前。读写使用非阻塞 socket，暂不可用时按剩余预算等待，不依赖内核 socket 相对超时。中英文均运行原来的 1.5 秒墙钟断言；macOS 测量前以一次 `--help` 排除新构建程序的系统首次装载/校验，每次被测 wait 仍计入 spawn 至退出的全过程。

已在修复前运行并确认失败的回归：`settings-limit.case.mjs` 四项、`timeout.case.mjs` 的 TERM 抵抗进程回收、CLI `tests/deadline.rs` 两项、Rust `deadline_includes_a_full_stdin_pipe_and_queued_writers`、`an_unterminated_frame_is_not_dispatched`。测试用例创建自己的临时目录和进程，并在失败时强制清理。

## 房间事务与历史（T5）

`rooms.json` v2 同时保存房间/任务状态、递增 revision 和每个账本的 `ledgerLengths` 提交字节游标。先同步追加事件，再原子替换该文件；重启只重放已提交前缀，重试先移除失败追加的尾部。追加、同步、rename 故障均保留上一完整提交。跨进程文件锁与 revision 比较拒绝陈旧实例覆盖。v1 在首次加载时迁移提交游标，旧应用无法写 v2 数据。通用原子写入在 rename 前同步临时文件；rename 后目录同步失败记录警告，因为此时新文件已经可见，不能告诉调用方“未提交”。

最近对话窗口仍为 1000 条；额外的 `retainedMessages` 保存仍待回复、未送达及被引用的消息。CLI 待回复列表与按编号回复同时查询两者。前端待回复入口应合并 `messages` 和 `retainedMessages`，按 ID 去重；普通时间线可以只显示最近窗口。

原始账本（包括未知 kind、未来版本和无法解析的行）保留到用户删除房间，不再在启动时按最近投影重写。附件文件同样跟随房间生命周期。因磁盘损坏导致已提交账本比游标短时只读运行并报告问题，保留现场。此策略有意保留完整历史；未来若加分页或分段归档，不能删除仍被回复、附件或待投递事项引用的记录。

已在旧实现确认失败的四项 `rooms_test::regression_*`：rename 失败后幽灵通知、超过 3100 条事件后失去早期待回复、未知事件被启动压缩删除、陈旧实例覆盖新提交。另有 append/sync/rename 注入、失败后重试只提交一次与截断账本只读回归。

T10 全量回归补强：Unix 文件锁守卫释放时显式 `LOCK_UN`，防止并发 `fork` 继承描述符后延长已结束的事务锁；独立 `dup` 回归在旧实现稳定失败，活跃守卫仍保持写入互斥。
