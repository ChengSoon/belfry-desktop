# Codex / Claude Code 原生终端状态

Belfry 使用 [Program Status Protocol 0.4（OSC 7501）](https://www.superlogical.com/rex/docs/build/program-status) 接收 Codex 与 Claude Code 的状态。CLI 在 PTY 输出中报告状态，原生后台解析并广播结构化快照；这两种 Agent 不再通过状态 Hook、屏幕文字或输出静默时间判断空闲。

## 能力探测与记录

CLI 发出 `ESC ] 7501 ; ? ST` 或 BEL 结尾的查询。后台应答：

```text
ESC ] 7501 ; ?:states=idle,working,done,blocked,error:kinds=permission,question,auth ST
```

Codex 的根记录使用 `app=codex`，Claude Code 使用 `app=claude-code`。只有当前会话 Agent 匹配、没有 `id` 的根记录控制前台状态；子记录不会使收件箱提前发送。有效示例：

```text
ESC ] 7501 ; state=working:app=codex ST
ESC ] 7501 ; state=blocked:app=claude-code:kind=question ST
ESC ] 7501 ; state=idle:app=claude-code ST
```

保存原始 `state`、`kind`、`progress`、Base64 编码的 `title` 与 `msg`。每条根状态更新生成单调递增的序号，快照来源为 `terminal_protocol`。解析支持分片、BEL/ST 终止与 CAN/SUB 取消，限制序列和记录大小。无效报告不生成空闲状态；根记录清除、终端重置或不匹配的根记录使状态未知。

## 消费规则

| 原始状态 | 界面与投递行为 |
| --- | --- |
| `idle` | 就绪；满足输入许可条件后可投递，不触发完成通知 |
| `working` | 正在处理；等待 |
| `blocked` | 等待权限、回答或登录；等待 |
| `done` | 本轮完成；满足输入许可条件后可投递，触发完成通知 |
| `error` | 本轮未完成；等待，触发失败通知 |
| `clear` / 缺少报告 | 等待原生状态；等待，不显示为正在处理 |

提示队列、协作收件箱、房间成员、名册、Git 反馈、工作台、侧栏、终端状态栏、通知与关闭提示从同一原生状态读取。其他 Agent 仍使用各自已有的状态接口。

## 原生输入许可

`idle` 或 `done` 是必要条件。自动投递还必须取得同一个原生输入许可：没有用户草稿、输入法组合输入、粘贴或未决投递，且 PTY 当前支持 bracketed paste。正文冻结后，连续且属于同一 Agent 的 `idle` / `done` 报告保留本次许可，包括 Codex 粘贴正文时的 `done → idle` 更新。经过忙碌、弹窗、错误、状态清除、报告缺失、用户输入或终端变化后，旧许可失效；正文及 Enter 写入前仍在 PTY writer 锁内复核。

用户输入独立跟踪，空闲报告不会清除草稿。已确认空白且就绪的输入框收到单独回车时保持空白，不等待不会产生的 `working` 报告；已有草稿或已预留粘贴仍按真实提交处理。预留粘贴不视为提交；回车实际提交后出现新的 `working` 报告，才确认输入已消费。

xterm 对光标位置、设备属性、模式和窗口查询自动产生的 CSI 应答走 `terminal_write_response`，由原生宿主匹配仍有效且未回答的查询。重复回放或过期应答直接丢弃，不写入 CLI、不推进输入代次，也不撤销自动投递许可。前端只在 xterm 的公开解析器产生回复时标记此来源；真实键盘、粘贴和 IME 仍走人工输入通道，不能凭字节形状借用应答标记。

Codex 可开启 DECSET 1003 和 SGR 鼠标上报；此时单纯移动鼠标也会产生终端输入字节。无按键的移动报告同样走 `terminal_write_response`，前端要求它产生于同一个 DOM `mousemove` 事件，原生侧再核验当前鼠标模式及报告格式。有效报告仍发送给 CLI，但不占用输入框、不撤销自动投递；退出鼠标模式或输出状态丢失后丢弃。点击、拖拽、滚轮及真实键盘／粘贴不能借用这个来源标记，已有草稿也不会被鼠标移动清除。

Esc、左右方向键、Home/End 与翻页键只移动光标、滚动或打断当前轮次，不修改输入框。它们可以中断正在进行的自动粘贴，但不推进输入代次、不清除待确认提交，也不把输入框标成草稿；否则在空输入框上按一次 Esc 就会一直显示「终端有未提交输入」。

按字节推断无法知道用户是否把字删光，所以挂载中的 Codex 视图会读取 xterm 缓冲里 Codex 自己画的空输入框提示（暗色的 `Ask Codex to do anything` 等），确认后调用 `terminal_confirm_empty_input`。原生只在没有已授权的自动写入或交互时清除草稿／未知状态，且前端要求空输入框连续稳定后才上报；透明背景会移除 dim，此时改用完整提示文本核对。Claude 的输入区版式尚未用真实屏幕验证，暂不参与该判定。无法确认时保持原有占用，不凭屏幕猜测放行。

收件箱的阻塞原因先看原生状态：Agent 正忙、缺少提交后的新报告等显示「等待终端就绪」，只有状态确实就绪时才显示「终端有未提交输入」或「等待确认终端输入状态」。

在同一宿主内重新挂载终端界面时，前端从原生宿主恢复已有输入所有权和待确认提交。重放中已经被宿主处理过的历史输出缺口只重建屏幕，不把已确认空白的输入框重新标为占用。跨宿主恢复或尚未处理过的输出缺口仍无法证明草稿已清空，收件箱显示「等待确认终端输入状态」；实际输入占用、安全粘贴未启用和原生状态未就绪分别显示各自原因。所有自动写入继续通过原生许可核验。

后台使用独立 `WriteChecked` 命令并声明 `terminal_program_status_v1` 与 `terminal_input_continuity_v1` 能力。新建会话使用支持连续空闲许可的后台，已有会话继续路由到原后台，并发送最新已核验的状态序号。旧后台不支持受检写入时关闭自动投递，不降级成普通写入。明确的零写入拒绝可退回队列；部分写入、I/O 错误或提交回执不确定时暂停，避免自动重贴。

## A2A 任务状态与 CLI 输入位置

A2A 的 `Task.status.state` 表示任务生命周期。Belfry 本地网关通过当前收件 Agent 的显式 `A2AReportTask` 回报及同一生命周期的权威任务板得到 `TASK_STATE_WORKING`、`INPUT_REQUIRED`、`COMPLETED`、`FAILED` 等状态。终端空闲、设备回复和屏幕重画不会完成 A2A 任务；任务卡与协议结果按这个结构化状态展示。

A2A 标准没有终端输入框是否为空的字段。本地 Codex / Claude 接入采用 `mcp-pty` 适配：A2A HTTP 接收任务后，由收件箱将指令送入 CLI，因此实际键盘写入还需 OSC 7501 前台状态和原生输入许可。A2A 的任务 `completed` 不清除用户尚未提交的新草稿。外部 Agent 的 A2A HTTP 请求不经过本地 PTY 输入拦截。「等待投递」统计房间消息，与仍在执行的 A2A 任务数量分别计算。

## 后台生命周期与升级

原生状态保存在终端后台会话中，独立于 Hook 缓存，恢复连接时回送最新快照。最终 `done` / `error` 与 Exit 同批到达时仍处理通知。终端查询应答使用有界队列和每会话一个 writer worker，避免输出 reader 等待大段输入写完。

升级应用后，宿主同时校验后台的应用版本和原生状态能力。版本不匹配时自动启动当前版本的后台，新建会话立即使用新版；旧会话按终端 ID 保留在原后台，输入、输出、身份和能力检查均路由到所属进程。正式版与开发版仍使用独立目录，无需重启电脑。

支持滚动升级的旧后台收到 `Retire` 后停止新建会话，继续提供运行中会话及已退出会话的输出记录。最后一条会话关闭后自动退出，并只清理自己发布的端点。旧版本未实现 `Retire` 时仍保留进程，但新宿主不再用它新建会话。恢复已退出的旧会话时在新版后台续接原生对话，创建成功后再关闭旧记录；失败保留旧记录，不重放上一次提示。Worktree 操作同时取得所有存活后台的租约。

运行中的旧 CLI/PTY 不能跨进程热替换，继续完成原任务；其旧后台缺少状态能力时自动投递仍等待，关闭或恢复会话后由新版接管。CLI 自身未提供匹配的 OSC 7501 报告时，应升级到支持协议的 CLI。设置不再提供 Codex / Claude 的新状态 Hook 安装入口，仍允许预览移除旧的 Belfry 托管 Hook。

回归覆盖解析、原生受检写入、后台恢复、输入占用、提示与收件箱队列、状态展示和通知。主要实现为 `src-tauri/src/terminal/program_status.rs`、`src-tauri/src/terminal/native.rs`、`src/agent/programStatus.ts` 和 `src/terminal/controller/protocolInputOwnership.ts`。
