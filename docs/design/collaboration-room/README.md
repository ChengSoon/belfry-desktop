## 这个原型是什么

房间是常驻的协作组：先把 Agent 拉进来，之后随时把任务发给他们；任务可以任意追加、并行推进，不绑定某个既定目标，也不预设协调员。同一个 Agent 可以反复添加为不同角色，每次生成独立 `memberId`、独立会话标识与职责。发送消息时选中接收者（可多选）即为派活，不选接收者就是普通讨论；派活消息会在时间线上内嵌一张任务卡片，点开即可查看执行状态、验收条件和证据。

全部为合成演示：不连接真实 Agent、不调用模型、不读写文件系统、不持久化任何内容，刷新页面即重置。示例 Agent 名称是配置名称，不代表系统已安装这些 Agent。

## 可实际体验的操作

- **房间**：新建房间只填名称；创建后是空房间，空态引导先拉成员进来。成员与任务独立于其他房间。
- **成员**：添加成员（同一 Agent 重复添加、角色同名自动递增、Agent 列表展示本房间已用次数）；成员详情显示职责、独立会话标识与负责的任务，可「派任务给他」、复制标识、「再添加一位」（复制角色仍生成新 memberId）。
- **讨论与派活**：输入正文后选择接收者再发送，即把任务派给选中的成员（可多选，发送后立即开始）；不选接收者就是普通讨论，不触发任何自动回复。Enter 发送、Shift+Enter 换行、中文输入法组合态不发送；`@` 点名与接收者选单都按 memberId 寻址；引用保留来源并可跳回原消息；「标记为决定」把结论写进右栏；左栏房间列表给不在场期间的新消息亮未读点（与未读分隔线同源，读到即灭）。房间条目显示最近活动时间（刚刚 / 钟点 / 昨天）。输入框打 `@` 弹出成员点名单（过滤、键盘选中、插入 `@角色`，发送时只发给被点的人）；房间列表按最近活跃排序。翻历史时新消息攒成「回到底部 · N 条新消息」浮标。
- **执行**：任务派发即运行（合成推进）；多条任务并行。每条任务可单独暂停（冻结进度）、恢复、停止（需要确认且保留已提交产物），提交后进入已提交待验证，验证独立于提交；任务详情展示派活内容、验收条件和证据。
- **产物**：查看合成规格、代码差异与验证记录；没有产物的房间显示空态。
- **布局**：标准协作 / 专注讨论 / 紧凑工作三种布局与深浅双主题；窄窗（≤1120）右栏、手机宽度（≤840）左栏收成抽屉，遮罩或 Escape 退出，输入区始终可见。

## 与现有代码的关系

已有会话协作代码（`src/collab/contracts.ts`、`src/collab/useTaskDelivery.ts`、`src/collab/CollabPanel.tsx`）提供了名册、派活投递和回传入口。本原型复用了它的术语与约束（memberId 寻址、任务路由到选中的成员、目标卡在权限框时不投递），但**没有**据此声称已有持久化、取消执行、独立会话创建或任务验收后端——这些都不存在。
