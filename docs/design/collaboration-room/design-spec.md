# Belfry 协作房间 · 交互设计

## 已确认的产品约束

> 修订（2026-10-28）：房间不再绑定目标，也不再预设协调员；房间是常驻的协作组，任务由用户随时发送给指定成员。以下约束与流程已按此版本实现。

- 房间只添加 Agent，不配置 Provider 或模型。运行配置属于 Agent。
- 同一个 Agent 可以反复添加，每次生成独立 memberId、角色、上下文和运行状态。
- 消息的作者、接收者、任务负责人均引用 memberId，不以 agentId 唯一寻址。
- 房间是常驻的协作组：不绑定目标；先把成员拉进来，之后随时把任务发给他们，任务可以任意追加、并行推进。
- 发送消息时选中接收者（可多选）即为派活；不选接收者则为普通讨论，公开讨论不触发任何自动回复。
- 房间包含公开讨论、共享决定、任务和产物。用户可以派任务、暂停/恢复/停止单条任务、验证交付结果。

## 本轮交付与假设

交付可点击的桌面优先 HTML 原型，接续现有 Belfry 工作台，不接入真实 Agent、文件系统操作或模型请求。界面持续标注「交互原型 · 示例数据」。登录体验升级只作为合成演示场景；示例 Agent 名称是配置名称，不代表系统已安装这些 Agent。所有原型状态刷新后重置。

已有会话协作代码提供了名册、投递和回传入口，但本轮新增房间界面不声称已有持久化、取消执行、独立会话创建或任务验收后端。本地事实来源：src/collab/contracts.ts、src/collab/useTaskDelivery.ts、src-tauri/src/collab/task.rs。不依赖仓库中已过时的 Harness 设计文档。

## 形式推导

1. 叙事角色：持续工作的协作空间。中央按时间阅读谁提出问题、谁给出决定、派了哪些任务，右侧稳定展示进行中的任务与进度，避免用户反复翻聊天寻找已确认结论。
2. 观众距离：桌面近距阅读，1440×960 为主，检查 1024×768、820×900、390×844。主正文 14px、辅助正文 12px；窄窗主动收起侧栏和上下文面板。
3. 视觉温度：延续现有 Graphite 石墨深色与暖白浅色；绿色只表示主要动作、选中和已完成，琥珀用于待验证和待处理。状态同时给出文字。
4. 容量：左栏 224px，右栏 296px，聊天保持可读行宽。会话正文、任务列表、弹层各自滚动；输入区始终可见。
5. 视觉母题：同一条讨论中不同角色的「署名」。头像字、成员姓名和 Agent 来源建立稳定的身份线索；相同 Agent 的多个角色并列显示，让产品的核心关系直接可见。

## 资产与设计系统

- Belfry 标志：复用 src-tauri/icons/128x128.png，不重画。
- 主题：以 src/styles.css 当前 token 为准。深色 canvas #171a19、surface #202422、accent #b2d5b6；浅色 canvas #fcfbf7、accent #285d37。
- 中文与拉丁文字：使用仓库 HarmonyOS Sans SC；路径、序号采用 JetBrains Mono。字体来自 public/fonts，400/500 字重。
- 参考画面：docs/design/production-ui/screenshots/workbench-dark-1440x960.png 已实际查看。
- 工具产品不需要装饰摄影或生成插图；不加入营销统计。
- 三种可切换布局：标准协作（默认三栏）、专注讨论（收起右栏、限制正文宽度）、紧凑工作（缩小间距、展示更多内容）。都复用已有品牌语言；支持双主题。

## 信息架构与关键流程

左侧列房间和当前房间成员，中央分「讨论 / 任务 / 产物」，右侧为进行中的任务、已确认决定与完成计数。移动端左右栏作为抽屉出现。

添加成员：选择 Agent → 填角色名称和职责 → 添加独立成员。Agent 列表一直允许重复选择，并展示本房间已使用次数。提供「再添加一位」，复制已有角色后仍创建新 memberId；名称同名时自动递增。成员详情显示职责、独立会话标识和负责的任务，可点名或复制，不出现模型选择器。

创建房间：名称必填；创建后是空房间，展示空态引导先拉成员进来。成员与任务独立于其他房间；不同房间保留各自的草稿和接收人选。

讨论：输入正文并选择接收者（可多选，选单与 @ 点名都使用 memberId）；按 Enter 发送、Shift+Enter 换行，中文输入法组合态不发送。选中接收者的消息同时派出一条立即运行的任务，并在时间线上内嵌任务卡片；引用保留来源。不选接收者的消息只是公开讨论，不触发任何自动回复。

执行：任务派发即运行：运行中 →（暂停冻结进度 / 恢复继续）→ 已提交待验证 → 验证通过；多条任务可并行。停止需要确认并保留已提交产物。验证独立于提交，任务详情展示派活内容、验收条件和证据。

产物：支持查看示例规格、代码差异与验证记录，以可阅读内容表达交付；所有内容均为合成示例。未生成产物时显示空态。

## 可访问性与验证

使用原生 button、form、dialog；所有图标按钮有名称。弹窗限制焦点、Escape 关闭、关闭后恢复焦点；抽屉用遮罩和关闭按钮退出。任务状态不只靠颜色。支持减少动态效果，页面无横向滚动。

用隔离 Chrome 检查：重复添加同一 Agent 后 memberId 不同、多选接收者派活并路由到各 memberId、房间隔离（讨论 / 成员 / 任务都不串房）、任务并行推进与暂停/恢复/停止/验证、产物、布局与主题、桌面/窄屏/手机、弹窗键盘，以及本地资产和控制台错误。
