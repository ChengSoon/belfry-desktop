# 协作房间 · P3 增强设计

[production-design.md](production-design.md) 的 P1 / P2 已全部落地。这篇把 P3 的五项增强逐条
落到「做什么、怎么做、风险在哪」，并记录第一项（`belfry rooms`）的实施结果。小节顺序即建议的
实施顺序。

## 1. `belfry rooms`：成员侧的房间可见性（已实施）

**目标**：房间成员在终端里看得见自己在哪些房间、成员是谁、有什么值得留意的活。

**落地**

- 协议（`belfry-protocol`）：`Command::Rooms`、`ResponseData::Rooms`、`RoomBrief` /
  `RoomTaskBrief`，camelCase，沿用既有 wire 风格。`PROTOCOL_VERSION` 不动：新命令是纯
  增量的，旧 CLI 永远不会发它，新 CLI 对旧 app 会在解析层得到「请求格式不对」，可接受。
- 服务端（`collab::server`）：新增 `RoomDirectory` trait 与 `RoomAccess` 挂载点。服务线程
  先于房间存储就绪（socket 要先于任何 PTY 存在），`OnceLock` 装好后所有请求自动看到真实
  数据；未就绪时如实回答「不在任何房间」。总线不回头认识 rooms，依赖方向仍是 rooms → collab。
- 房间层（`rooms::store`）：`impl RoomDirectory for RoomStore`。只报「值得留意的活」：进行中、
  待验证、等重派；已验证 / 已退回 / 已停止的已经结账，不进清单。接收者用角色名而非 tabId。
  阶段中文名（`stage_label`）与前端 `src/rooms/model.ts` 的 `stageMeta` 同一口径，两侧各有
  测试钉死。
- CLI（`belfry-cli`）：`belfry rooms` 渲染房间名、我的角色、成员、活与接收者；空清单明确
  说「不在任何房间」。技能说明（`skills/belfry/SKILL.md`）已补对应小节。

**决策**：不暴露 token 与 PTY 内部状态；成员能看到的内容不超出「用户把它拉进房间」这个动作的
授权范围。

**未决**：成员向房间的「回报进度」写入路径。现在房间时间线只有用户派发与系统事件，成员的回话
走 inbox / done 回流不到房间里。需要时按「成员消息 = 系统事件」设计，等真实需求出现再做。

## 2. 产物快照：交差时采集 diff（已实施）

**目标**：成员交差的那一刻把工作区 diff 采下来附在任务上，验证时不只凭一句自述。

**落地（与原稿的差异已回写）**

- 采集点放在对账路径而不是 `belfry done` 响应路径：对账只在「有投递交差、且快照缺失或落后于
  最新一次交差」时才去读 git，幂等且不做无谓开销，省掉了给 done 响应带房间上下文的协议扩展。
- 采集内容：`git diff HEAD --`（无提交历史退回 `git diff --`），不含未跟踪文件；上限 32 KB，
  截断如实标注。空差异也写成快照——「交差时工作区没有改动」本身就是一句证据，也才能让幂等
  检查停下来。
- 采集失败的根（不在 Git 仓库、git 报错）进程内记忆不再重试；目录后来才变成仓库时，重启应用
  即恢复采集。
- 存储 `RoomTask.artifact`；任务详情「证据」折叠区展示；验证记录导出带摘要行。

**局限**：快照是「对账时刻」的工作区状态，不是任务开始时的基线——成员交差后又改了工作区，
下次交差会刷新快照，中间态不留档。需要历史版本时再引入基线锚点。

## 3. 跨项目房间（已实施）

**目标**：一个房间拉进不同项目的会话。

**落地（含原稿未决项的定案）**

- 数据：`Room.extra_roots`（serde 默认空，旧档照常读）；接活范围 = `project_root` + `extra_roots`。
- 扩展的入口：`room_add_member` 带可选 `project_root`——成员会话在哪，房间范围就顺势扩到哪，
  系统消息留痕，重复扩展是空操作。**2026-10-29 定调**：添加成员对话框收敛为「选 Agent →
  创建」，成员一律在房间项目里新建、不再挑已有会话；扩展机制保留在存储与协议层，留给以后
  「拉入已有会话」之类的入口。
- 闸门：`judge` 一字未改，只把 `prepare_dispatches` 的「与房间同项目」判定换成房间范围的
  `covers_project`。范围外项目的拒绝路径一个字不变。
- **范围只增不减**：成员离开或换项目都不自动收紧——收紧会静默掐掉某些成员的派发，那是用户
  没点头的破坏性动作；要收紧留给后续的显式操作。
- 界面：房间头部显示项目范围——成员都在房间项目里时就是一个路径；范围扩过之后显示
  「主项目 等 N 个项目」，tooltip 列出全部根。

**风险与缓解**：同一条会话同时属于两个项目的房间时，同一条派发在两个房间可能得到不同结论；
头部范围标注与系统消息让这件事可解释。三个以上项目的房间暂时没有专门可视化，真实用到再补。

## 4. 房间模板（已实施）

**目标**：一键建出「实现 + 审查」这类常用班子。

**落地（原稿定案的执行）**：纯前端常量模板（`src/rooms/templates.ts`：名称 + 角色清单，角色带
推荐 Agent），创建房间时可选、不落库。选模板自动填房间名，并预览「创建时会拉起」的班子；
创建房间后逐个拉起成员会话并按角色命名。

**两个决定**：推荐 Agent 装了就按推荐，没装退回第一个可用的，预览如实显示会用谁；某个成员
没起来就停在那里——房间和已建成员都保留，缺的用「添加成员」补，比回滚半个房间诚实。

**未决**：自定义与持久化模板按原稿仍不做，等常量模板真被常用起来再说。

## 5. 多窗口：房间独立窗口（已实施，v1）

**目标**：房间视图独立开窗。

**落地**：主窗口房间头部「在新窗口打开」→ `room_open_window` 起一个 `room-<id>` 窗口
（`?room=<id>` 启动同一份前端，只挂房间视图，没有工作台外壳）；重复打开只聚焦已有窗口。
看、派、验、停、退回、标记决定、改名删房都直接可用——它们都是全局命令；投递与提醒仍由
主窗口执行。原稿担心的 `is-rooms` 整窗互斥在新窗口里不存在：独立窗口没有外壳，
互斥语义只属于主窗口。

**在场状态的来源**：读协作名册快照（`collab_sessions`，2.5 秒轮询）。名册本来就是派活
闸门读的同一份真相；不走 localStorage 存档——存档里的 phase 是恢复初始态，画出来会全员
假离线。

**边界（有意收敛的 v1）**：「添加成员」与「模板建班子」留在主窗口（新建会话必须落进主
窗口的会话清单才算数）；文件回执在独立窗口里按纯文本显示；提醒通知只挂在主窗口，
独立窗口不重复发。

**风险**：名册由主窗口推送，主窗口不可用时独立窗口的成员一律显离线；应用退出时独立
窗口随进程一起消失，不构成新的一致性窗口。

**未决**：在独立窗口里加成员的桥（主窗口代拉会话、结果回传）先不做，真实用起来嫌绕再补。

**验收现状**：独立视图本身、`?room=` 启动路径与开窗调用在浏览器用例里全覆盖；真实窗口的
开/聚焦/关闭属发布前手动检查（和 `belfry rooms` 同一条手动单）。

## 6. 房间群聊：成员互通（已实施）

**目标**：房间是真正的群聊——所有人都在场里说话，消息默认送到每个成员，能互相点名、
也能彼此接话；不是只把派发任务堆在一起。

**定调（2026-10-29，用户）**：群聊的要义是「不被点到的人也在场」。最初只做「@才送达」，
被否掉；改成**不点名＝发给全体**，点名才收窄到被点的人（收窄一项后被「修订二」改掉：点名改为口径分层，不再收窄送达，见下）。

**落地**

- 用户消息：不选接收者直接发送＝群发给全体成员（`room_broadcast`，忙碌的成员排队而不是
  把整条群发拒掉；会话不在的成员跳过并如实体现；一个都投不出去时退化为只记录）。先选中
  成员再发＝只派给他们（原 `room_dispatch` 闸门保留）。
- 成员发言（`belfry room say`）：不带 `@` 发给所有其他成员，注入文案是「看见即可」（修订二前为「对大家说」）；
  `@角色` 请被点的人接话（2026-10-29 修订二后不再收窄送达：所有人都收到，「请你说」与「看见即可」两种口径）。投递复用既有队列与背压，不走 `judge`：房间
  成员资格就是用户的授权。时间线的消息上只标显式点名，不刷一排全体标签。
- `belfry room log`：成员读房间最近的对话（默认 20 条、上限 50；多间房用 `--room` 消歧）。
- 交差回显：成员交差带结果时，时间线里以它的口吻出现一条消息（「前端：都改好了」），
  不再是系统摘要；没带结果的交差仍留系统消息。回显消息不挂任务卡——卡只在发起消息
  下面出现一次，免得每条回话都拖着同一张。
- 回执一眼可见：时间线任务卡带「已交差 x/y」；收件人标签直接演状态——转圈＝还在回复
  （排队 / 已送达）、勾＝交差、红叉＝失败、虚框叉或问号＝已停止 / 结果未知，悬停给出
  回执文字；任务卡计数在还有成员没回时带同款转圈。谁在回、谁还没回不用点开。
- 时间线按聊天对话排版：头像在行首（首字方徽，成员取角色首字、用户是「我」），名字和时间
  在其上方，正文收在气泡里；自己的消息靠右、成员的消息靠左；任务卡片与收件人标签跟在
  气泡下方。系统事件保持居中的日志行。
- 限速：一间房一分钟最多 12 条，超了当场拒绝。
- 成员间转手的回复回时间线（2026-10-29）：成员把活转给同房的其他成员后，对方交差时回复
  以本人的口吻回显进时间线——之前这条链路断在交接处（转手任务不在房间任务表里，对账
  扫不到）。`send` 直派在时间线补系统留痕「「A」把任务交给了「B」」，点名转手不加
  （消息本身就是痕迹）；群发讨论不登记（给讨论也记一笔，重启后的「没能送达」会把时间线铺满）；任务记录丢失（应用重启）如实标注一次，停止 / 作废不宣布只记结。

- 点名口径分层（2026-10-29 修订二）：「@ 一个角色后其他成员收不到、被关在门外」被确认为语义缺陷。点名不再收窄送达——投递到所有其他成员；被点的人注入口径「请你说」，其余人「看见即可」；时间线仍只标显式点名。回复照旧走 `room say`。

- 用户点名同义（2026-10-29 修订三）：用户在群聊消息里写的 `@角色` 与成员发言同义——送达范围不变（投递到全体成员），被点的人收「请你说」口径、其余人「看见即可」；`mentions_in` 复用成员发言同一把解析尺（长角色名优先、`@审查员` 不算点名），`room_broadcast` 逐位成员给口径标志。

- 引用回复与未读分隔线（2026-10-30 修订四，参照同类项目）：引用让对话不必靠上下文猜指代——消息悬停可引用，引用块可跳回原消息，目标被清后如实标注；未读分隔线回答「我不在的时候群里说了什么」，已读位按房间记在本地，重进把新消息标出来，点掉即读。不做独立线程泳道（引用已给 80% 价值），不引入中央调度（保持注入文案的社会规范）。

- 成员引用回复（2026-10-30 修订五）：`room log` 每行带短 id；`room say --reply <id>` 引用回话，注入行带原话摘录（`SayOutcome.reply_preview`），指代不靠猜；目标不存在当场拒绝。前端复用既有引用块渲染，成员消息自动获得引用样式。

- 表情回应（2026-10-30 修订六，参照同类项目）：用户悬停快捷回应、成员 `belfry room react <短id> <表情>`；一人一表情切换语义、白名单六枚；`room log` 带计数。只记「谁给了信号」这个事实，不假装读心；不注入终端、不占成员上下文，是最轻的「我看见了」。

- 未读落地与 log 引用（2026-10-30 修订七）：重进落在第一条未读（分隔线在视口内才有意义），已读位点掉才推进（治「分隔线莫名消失」）；`room log` 带引用摘录、用户消息标「用户」——log 是给成员补课读的，两个口径都要对。
- 输入法选词回车不误发（2026-10-30 修订八，用户报告）：macOS WKWebView 上确认候选的回车 `compositionend` 先于 `keydown`（WebKit bug 165004），`isComposing` 已为 `false`，只剩 `keyCode 229`（VK_PROCESS）可认——新增 `composingKey` 共享判定（`src/utils/keyboard.ts`），全应用 34 个文件的按键守卫统一收编（composer、对话框、搜索框、下拉控件、Escape 处理、`chord.composingInput`）；浏览器用例按真实事件形状补「选词回车不发送 / 真回车照常发送 / 对话框不提交」断言。另把「事后 229」的默认动作一并挡住：composer 防多补换行（`suppressComposingEnter`）、9 个含文本输入的表单挂 `guardComposingEnter` 防隐式提交；只挡 WebKit 这种事后形状，真回车照常发送 / 提交。
- 房间列表未读标记（2026-10-30 修订九）：`RoomSummary.lastMessageAt`（Rust 对 messages 取 max，清空后 None）+ 本地已读位渲染未读圆点；与修订七的未读分隔线同源——亮 ⟺ 进房会画分隔线，读到即灭，从未进过的新房不亮。浏览器用例按「不在场时亮 / 只亮说话的那间 / 读到熄灭」三断言收口。
- 最近活动与未读条数（2026-10-30 修订十）：房间条目副行显示 `formatRoomActivity`（刚刚 / HH:MM / 昨天 / 月日）；未读分隔线带「以下为 N 条新消息」——真人聊天里「多久没动静」「攒了多少条」是两个最基本的感知信号。
- @ 点名单与按活跃排序（2026-10-30 修订十一）：composer 打 `@` 弹成员点名单（在场成员为候选、输入即过滤、方向键/回车选中、Escape 只收名单；选中插入 `@角色 `），与后端点名解析同一把尺；房间列表按 `lastMessageAt` 排序，最近有动静的排最前。
- 回到底部浮标（2026-10-30 修订十二）：翻历史时新消息的增量攒成「回到底部 · N 条新消息」；零高度锚不占布局；贴底/分隔线/搜索不重复计数；点击或滚回底部即清。
- 点名收窄投递（2026-10-30 修订十三，用户报告）：修订二的「全员送达、口径分层」不符预期，改回：`store::chat_targets`（成员发言与 room_broadcast 共用）点名收窄到被点者、不点名发给全体；被点者转手交差仍回时间线；前端按钮按 `model::mentionedMembers` 显示「发给 X」。
- dev 后台隔离（2026-10-30 修订十四，用户报告「界面中没有回复信息了」）：dev 与正式版同 identifier，dev 复用正式版守护进程，而守护进程推的 CLI 取自自己的安装位置 → dev 里的成员拿到正式版旧 CLI（不认 `room`），收得到消息却回不了话。修复：`terminal::daemon::directory_name()` 让 debug 构建用 `terminal-daemon-v1-dev`，各起各的后台。
- 撤回消息（2026-10-30 修订十五）：`RoomMessage.recalled_at` + `room_recall` + `TaskBoard::drop_pending_message`（`ChatDelivery.lines` 按下标摘行）——还没送出的当场撤掉，已进终端的如实标注撤不回；成员 log 读「已撤回」；派活消息不走撤回。
- 气泡内 @ 提及高亮（2026-10-30 修订十六）：`model::mentionSpans`（自 `mentionedMembers` 抽出）+ `splitMentions`；气泡先切点名后切路径，芯片化显示，与「@ 谁只发给谁」对应；用全部成员（含离场者）以便历史消息也亮。

**风险（放大效应）**：每条群发＝N 个成员各收到一条注入、各占一轮 Agent 工作量，回复再
互相群发会级联。护栏：限速、逐任务停止与协作面板的一键全停、以及「只选部分人」的收窄
发送；房间人越多越要克制群发。

- 群聊通道（2026-10-29 修订，用户目标「更像真人在群里沟通」）：成员发言与用户群发不再包成
  交差任务——注入文案写明「看见即可 / 点名回一句 `room say`」，不要求 `done`；20 秒内的连发
  合并成一条注入；群聊不进收件箱与协作面板，送达由对账把回执写回消息（`delivered_to`，只记送达）后回收任务。回复直接走 `room say`，
  时间线成环，不再依赖交差回执。

**未决**：要不要给「只记录不发送」留一个显式入口；已读未读、只看 @我 这类细节按需再补；
成员消息暂不支持编辑或撤回。

## 7. 成员会话的隔离（已实施）

**目标**：房间里的角色只在房间里露面——侧栏、Quick Open、⌘1-9 都不列成员会话，
它们不再和用户自己的工作会话混在一起。

**落地**：房间摘要在 `member_count` 之外补 `member_tab_ids`（在房成员的 tabId）；
前端 `useRoomBoundTabs` 轮询摘要得到隔离名单，侧栏、Quick Open 与 ⌘1-9 都按过滤后的
列表走，关掉房间视图时顺手刷新一次，不让成员在侧栏里闪一下。只隔离展示层：成员会话
照常运行、接收投递、进协作名册、随工作区持久化。

**口径**：移出成员或删掉房间后，那条会话自然回到普通列表——它本来就是真实会话，
隔离是为了少添乱，不是为了藏东西。外面看不到，房间就把会话生命周期管起来：成员行上
有「关闭会话」，确认后结束进程并移出房间（先关后移，免得它在侧栏闪一下）；只主窗口
提供，独立窗口的能力收敛不变。成员行排成「状态点 / 角色与在场行 / 清除 / 关闭 / 移出」，副行只显示「在场状态 · Agent 类型」，操作按钮悬停才现身（「清除上下文」只主窗口提供、且该 Agent 有重置命令时才出现：把重置命令送进它的终端清空对话记忆，进程与会话不动）。成员行本身可点击：终端直接嵌进房间右栏，不离开房间就能实时看它干活（按标签接驳已跑的守护会话，工作台正流着同一条也不挤占）；点另一位成员直接换看、不必先收起（终端整块重挂，接驳身份跟着新标签走）；再点一次或「收起终端」把右栏让回给「任务与决定」。房间记住最后看的那间（localStorage），回来不跳走；右栏宽度可拖动（双击复位），「任务与决定」与终端两种形态共用一份宽度。

  真实会话里 `belfry rooms` 在房间里返回房间名与成员、不在时明确说不在（属发布前手动检查单）。
