# Belfry 全局 UI 重设计 · 原型设计规范

## 授权与交付边界

用户要求重新设计全部 UI，并明确「你定」设计方向。此次先交付覆盖主要宿主界面的可交互高保真原型，供用户实际查看后再分批接入生产 React。不是生产 UI 已完成的声明；不修改业务、IPC、安全存储或终端生命周期。M1 Provider 凭据保护、并行 hooks/输入改动保留。第三方插件自有页面不强行换肤。

## 产品事实与现有资产

事实来自当前仓库，不引用外部品牌或对版本作未经验证的公开断言。Belfry 是本地优先、多项目、多终端及 CLI Agent 的桌面工作台。现有界面有会话侧栏、可拆分终端、项目库/命名工作区、SSH、Quick Open、协作、文件/Git、历史、用量、设置、插件中心与后台会话管理。设置目前包括外观、全局 Provider、项目 Provider、会话状态、快捷键、本地备份、协作环境、插件和关于。源文件依据：src/components/Workbench.tsx、WorkbenchToolbar.tsx、AppOverlays.tsx、src/workspace/components/Sidebar.tsx、src/settings/SettingsPanel.tsx 及对应模块。

品牌资产：使用 src-tauri/icons/icon.png 原有 Belfry 图标（原型 assets/belfry.png 为其副本）；参考现有 docs/screenshots 下工作台/Provider/用量/插件截图，不重新制作 logo。字体沿用 public/fonts 的 HarmonyOS Sans SC 400/500 与 JetBrains Mono 400/500/600；中文不假设额外粗体已存在。工具产品不需要装饰摄影、生成人物或视觉填充图。主方案的绿色是拟议的新交互强调色，不是声称原品牌规范；当前主色为蓝色，源于 src/styles.css。

## 受众与设计目标

面对长时间同时管理多个项目、多个 Agent 和 Shell 的开发者。其核心操作是定位正在运行的会话、确认协作结果、查看文件改动、调整 Agent 连接、恢复历史与维护工作环境。界面不能把开发者工具变成漂亮但低密度的营销仪表盘，也不能为了视觉一致性让操作藏进多级菜单。我们希望打开后先看到在做什么、在哪个项目、什么需要处理，再看到可执行动作。终端内容是主角，外壳不与输出竞争。状态不能只靠颜色；「已配置」「已选用」「连接已验证」「应用于新会话」不得互相混淆。命令与路径采用等宽字体，正文和表单保持稳定阅读密度，主要操作有唯一明确的视觉主次。

## 形式推导

- 叙事角色：工作台是持续工作的场所，不是 hero landing page；设置是解决问题的表单，协作是决策队列，历史是可恢复的索引，用量是来源明确的数据视图。
- 观众距离：桌面笔记本近距阅读。原型目标 1440×960，也检查 1024×768 和 820×900；字体缩放到 200% 时允许面板内部滚动，不截断核心动作。
- 视觉温度：安静、精准、带少量暖意。深色使用石墨而非均匀深蓝，亮色为纸白；一个低饱和强调色贯穿动作，琥珀只用于待确认，错误有文字和恢复动作。
- 容量：工作台左导航约 220px，终端主区至少占剩余空间的 2/3，右侧上下文面板可关闭。设置分组导航与内容区分离，列表优先行而非堆叠大卡。窄窗口不强留三列；切为可收起侧栏或单列详情。
- 视觉母题：并行会话的「轨道」。通过稳定的纵向导航、细分隔线、会话名/状态/项目的对齐关系形成秩序，跨页面保留同一上下文和返回路径；不是套通用 SaaS 数据卡模板。

## 系统与变体

主方案 Graphite：石墨深色 + sage 绿色动作，8px 节奏，柔和 6–10px 圆角，靠表面亮度与排版分层，尽量少双重边框；正文 >=14px，辅助标签 >=12px，文字对比 >=4.5:1。交互反馈 120–160ms，遵守 prefers-reduced-motion。

变体 Paper：暖白编辑式版本，内容区更加平面、分隔更明确，浅色终端的命令仍清晰；不是纯换背景，适当改变内容区密度和栏宽。

变体 Compact：高密度开发者版本，更窄导航/更紧凑行距和顶栏结构，颜色保持克制。三个变体共用真实的产品功能与明确标注的演示数据，无外部产品 logo、无假客户证言、无捏造统计。

## 覆盖矩阵及真实可交互要求

1. 工作台：项目切换、会话选择、新建会话菜单、单/双终端切换、右侧待确认/文件上下文；演示终端输出明确仅为样例，不执行命令。
2. 项目库/工作区：本地项目列表、筛选、工作区选择、新建项目/工作区弹窗，远程状态。
3. SSH：主机列表、认证方式、端口/路径表单，连接模拟成功/错误，不能要求真实密码或联网。
4. Quick Open：⌘/Ctrl+K、过滤导航目标、Enter 选择、Escape 关闭和焦点返回。
5. 协作：等你确认/进行中/已结束过滤，查看结果、接受/退回演示状态，保留待确认入口。
6. 文件与 Git：文件树、选中文件、差异视图、预览开关；不访问真实项目文件。
7. 历史：搜索、来源/项目筛选，恢复演示会话；空结果提示。
8. 用量：时间范围/当前项目作用域切换，数据来源/成本估算边界；数据必须标注「演示数据」。
9. 设置全部栏目：工作环境（外观/快捷键）；Agent 与连接（全局 Provider/项目 Provider/会话状态/后台会话）；扩展（插件）；数据与安全（备份）；帮助与诊断（环境/关于/更新）。保留已有入口语义，不凭空增加账号/SSO/云同步。
10. Provider：按 Agent 切换、全局/项目作用域说明、官方与自定义服务，已配置/未配置；编辑保留/替换/清除，端点变更 keep 必须拒绝；敏感原始配置显式 opt-in，用合成占位文本；关闭/切换清理；未保存保护。
11. 插件中心：已安装/市场切换、搜索、详情、权限/来源、模拟启用/禁用；不把普通 worker 说成安全沙箱，不真正安装下载。
12. 通用组件：新建/编辑、危险确认、未保存离开确认、loading/empty/error 状态、toast、kbd、按钮/输入/选择/切换；焦点环、弹窗 focus trap、Escape 和焦点归还。

## 验证与落地

原型仅使用本地资产和示例状态，不调用 Tauri 或真实系统/生产 API，无遥测，不写 API Key localStorage。若有本地偏好持久化仅允许 theme/variant。

验证需在独立无用户数据的 headless Chrome 中运行：所有导航及设置项能进入；主题/变体切换；Provider 编辑、端点动作与敏感预览门禁；未保存提示；Quick Open 键盘交互；弹窗 Escape 和焦点 trap；至少三个尺寸无页面级横向溢出；控制台异常为零；截图输出放 session scratch。真实 Tauri/WebView、原生窗口拖动、PTY 连续运行及 Windows 集成不由原型测试替代。

生产落地顺序为基础 tokens/控件 → 工作台外壳 → 设置/Provider → 次级面板 → 插件宿主/通用弹窗。每批独立测试和视觉验收，不全量重写 React 架构。落地前以用户看过的原型方向为准。
