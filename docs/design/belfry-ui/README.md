# Belfry 全局 UI 重设计 · UI study 01

## 打开入口

- [可交互原型](index.html)：完整应用外壳、页面导航与模拟操作。
- [方案对比](showcase.html)：Graphite / Paper / Compact 三种桌面截图，可一键切换。
- [设计规范](design-spec.md) 与 [品牌资产说明](brand-spec.md)。

直接在仓库原位置打开 HTML，或用工作面板预览；图片和字体是本地相对路径，不依赖 CDN。若移出此目录，需要同时保留 `assets/`、`previews/`、JS/CSS 以及仓库 `public/fonts/` 的相对位置。本轮交付为设计原型，**尚未替换生产 React/Tauri UI**。

## 设计方向

主方案 **Graphite**：石墨灰、低饱和绿色动作、稳定的项目 / 会话 / 工具轨道，终端内容占主区。状态由文字和颜色共同表达，待确认结果独立呈现。

- **Paper**：暖白、平面表面与更宽松的编辑式间距。
- **Compact**：更窄的导航、更紧凑的操作外壳，正文/终端输出不缩成微小文字。
- 两种主题可以独立切换，所有演示状态仅保存在当前页面内存中。

形式来自 Belfry 的并行会话和项目上下文，而不是营销仪表盘；不加入装饰摄影、通用科技渐变或虚构业务指标。

## 视图覆盖

8 个主视图：工作台、项目与工作区、SSH、协作、文件与 Git、历史、用量、插件中心。

11 个设置子视图：外观、快捷键、全局 Provider、项目 Provider、会话状态、后台会话、插件、本地备份、协作环境、关于、更新。设置总入口是别名，实际独立视图为 **19 个**。

通用流程包含 Quick Open、项目/工作区/会话创建、Provider 编辑、主机认证、插件权限详情、危险确认、未保存确认、loading/empty/error 与 toast。不是逐一复刻每个现有子控件；壁纸调整、计价规则编辑等细粒度生产设置仍需在实际落地时统一样式。

## 可实际体验的操作

- 顶栏选择项目、主题、Graphite/Paper/Compact；侧栏定位页面和演示会话。
- 单/双终端切换、待确认队列开关、创建演示会话、历史搜索/筛选/恢复。
- `⌘ / Ctrl + K` 打开搜索，方向键移动、Enter 打开、Escape 返回；`⌘ / Ctrl + B` 切换侧栏。
- Provider 按 Claude Code / Codex / Pi 查看；全局与项目覆盖分离；保留/替换/清除、端点变更保护、非空替换校验。
- Provider 编辑未保存时，关闭和路由离开会弹确认；原始配置只在显式 opt-in 后显示合成文本，关闭清空。
- 协作接受/退回、插件搜索/详情/启停/模拟安装、SSH 添加/编辑/认证方式/模拟成功失败、用量时间和作用域切换。
- 本地备份、环境检测、更新与快捷键冲突检查均为演示流程。

## 数据与真实行为边界

全部项目、主机、终端文本、文件差异、用量和插件信息均为明确标注的合成样例。主机和 Provider 使用 `*.example.invalid`。不要输入真实密码、Key 或私钥路径。

不连接真实服务、不读取本机项目、不调用 Tauri、不执行终端命令、不下载插件、不写配置或系统凭据，不持久化 Key。Provider 密钥文本只在弹窗 DOM 中存在，保存仅更新「已配置」布尔状态，输入清空。刷新重置全部示例状态。

演示的「已选用」不代表连接已验证，终端固定输出不代表真实 Agent。原型中作用域/生效提示用于表达设计，不替代各 CLI 的实际兼容语义；生产落地必须保留 Claude 后续请求生效、Codex/Pi 新会话生效等既有区别。第三方插件内部页面不强行换肤，普通 worker 不被称为安全沙箱。

## 本轮验证

执行：

```sh
BELFRY_UI_ARTIFACTS="$PI_SCRATCH_DIR/ui-redesign" \
node --test --test-concurrency=1 \
  docs/design/belfry-ui/prototype.case.mjs \
  docs/design/belfry-ui/prototype-flows.case.mjs
```

**结果：9 项通过、0 失败、0 跳过。** 独立临时 Chrome profile，结束自动清理。

覆盖：主要导航及全部 11 个设置栏目；主题与三种变体；1440×960、1024×768、820×900 布局；所有设置在 720×480 缩放等价视口下无页面/面板横向溢出（不是 OS 原生 200% 缩放验收）；Quick Open 键盘过滤、局部结果滚动与焦点返回；Provider 凭据动作、敏感预览门禁、未保存确认、弹窗 focus trap；会话创建/恢复、协作、插件权限、用量作用域、SSH 错误恢复。

测试检查无未处理异常、无 console error、本地资产加载成功、无凭据 localStorage；核对深浅主题基础正文与辅助文字对画布对比度 >=4.5:1。不是全量 WCAG 审计。

JS `node --check` 和本目录新增文本文件 whitespace 检查通过。三种方案桌面截图位于 `previews/`；完整测试日志及 Provider/弹窗/设置/窄屏截图在会话 scratch `ui-prototype-tests.log`、`ui-redesign/`。工作面板查看过实际方案画面。此次仅新增原型文件，未重跑不相关的 pnpm/Cargo 产品回归，也不引用历史结果冒充本轮验收。

## 生产落地顺序

1. 基础设计 tokens、字体、控件、焦点与弹窗：映射到现有主题和用户排版选项，不覆盖用户偏好。
2. 工作台外壳、侧栏、工具栏、终端标题与上下文面板：保留 PTY 挂载、输入、分屏/拖动/恢复行为。
3. 设置分组与 Provider：保留 section key、入口、未保存保护和 M1 凭据契约，不引入真实用户迁移。
4. 项目/SSH、协作、文件/Git、历史、用量等次级面板：保留数据来源、错误恢复和懒加载故障处理。
5. 插件宿主中心、启动器/工作面板及通用弹窗：不扩大权限，不改变第三方插件内部样式。

每批独立跑定向测试、前端完整回归、生产构建和相关浏览器检查，并分别进行深浅主题、窄窗、长文本、键盘和真实 WebView 检查。进入产品代码前，以用户看过的主方案为准。

**剩余工作：生产 React 落地、macOS/Windows 原生 WebView/窗口行为、真实终端持续运行与既有全功能回归。** 原型测试不替代这些验收。
