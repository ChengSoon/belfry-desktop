# Belfry 干活看板 · 交互设计

## 已确认的产品约束

- 看板把一件事摊成看得见的活：**节点**是一位负责人手上的一段活，**边**是一条依赖或一次交活。图上没有「谁先干」的隐含秩序，顺序只由连线表达。
- **不引入中央调度器。** 不设「主代理」替用户决定先做哪件：连线由用户画，派活由用户点。谁等谁必须在图上看得见，而不是藏在某个协调者的记忆里。
- **派活不等于做完。** 状态措辞沿用协作总线与房间视图的立场：`已送出` 只表示指令进了对方终端，完成只认对方自己交的差；没有执行证据的一律标「未验证」。
- 节点绑定真实会话：节点上的团队角色名就是 `belfry` 的寻址键（`src/workspace/contracts.ts` 的 `agentName`）。同一 Agent 可以出现在多个节点，各持独立会话。
- Token 用量与耗时来自会话统计（`src/usage/session`）；拿不到就写「暂无数据」，不拿计时器冒充预算，也不虚构费用。
- 一个节点只装一件事。需要并行的活拆成两个节点，而不是给一个节点堆两个负责人。

## 本轮交付与边界

交付桌面优先的可点击 HTML 原型，纯合成数据：不连接真实 Agent、不调用模型、不读写文件系统、不持久化（刷新即重置）。界面持续标注「交互原型 · 示例数据」。所有节点上的角色、路径、用量、转录都是编造的示例，不代表本机安装或执行过任何东西。

本轮改动只落在 `docs/design/flow-board/`，不碰 `src/` 与 `src-tauri/`，不声称生产已具备本看板。

## 形式推导

1. 叙事角色：这是工作台的**施工图**，不是仪表盘。用户来这里是拆活、连活、看谁卡住了，然后回到终端把活做掉。
2. 观众距离：桌面近距阅读，1440×960 为主，另检查 1024×768、820×900、390×844。正文 14px、辅助 12px。
3. 视觉温度：延续 Graphite 石墨深色与暖白浅色。绿=可派活/已完成，琥珀=待验证/等你确认，红=交不了；状态一律带文字，不靠颜色单独表意。
4. 容量：左栏 224px（流程列表、节点库、图例），右栏 320px（选中节点详情），中间画布自适应并允许平移缩放。
5. 视觉母题：**卡片 + 连线**。卡片承载「谁在做什么」，连线承载「谁等谁」；连线在依赖未满足时是虚线，可派时变实线，已交活时收成一条细实线并标注产物。

## 资产与设计系统

- 主题 token、字体、图标与 `docs/design/collaboration-room/` 同源：深色 canvas `#171a19`、surface `#202422`、accent `#b2d5b6`；浅色 canvas `#fcfbf7`、accent `#285d37`。中文字体 `public/fonts` 的 HarmonyOS Sans SC 400/500，路径与编号用 JetBrains Mono。
- 图标为内联 `<symbol>`，不引第三方图形；Belfry 标志复用 `src-tauri/icons/128x128.png`。
- 全部本地相对路径，无 CDN、无外部字体、无跟踪脚本。原型目录自带 `styles.css`、`app.js` 与浏览器用例夹具，可直接在仓库原位打开。

## 信息架构与关键流程

- **左栏**：流程列表（含各自「有活可派」小点）、节点库（点一下加到画布，或在画布空白处点击后选择类型）、图例。
- **中栏**：工具条（新建节点 / 连线 / 自动布局 / 适应窗口 / 缩放 / 合成推进开关 / 跑整条流程）+ 画布。
- **右栏**：选中节点的详情——状态、模式、团队角色、Token 用量、耗时、共享任务、前置与后继、验收条件、产物、查看转录，以及针对当前状态的操作按钮。未选中时显示流程概况：可继续的节点、被前置卡住的节点、已完成计数。

### 状态与派生规则

派生只依赖连线与各节点自身状态，规则写死在 `app.js` 的 `deriveStatus`，与界面文案同处一份：

| 状态 | 文案 | 派生规则 |
| --- | --- | --- |
| `waiting` | 等待前置 | 还有前置节点没到「已完成」 |
| `ready` | 待命 · 可继续 | 无前置，或前置全部已完成 |
| `running` | 进行中 | 已派活，尚未交差 |
| `submitted` | 已提交待验证 | 对方交差了，等用户验证 |
| `verified` | 已完成 | 用户验证通过 |
| `failed` | 有人交不了 | 对方明确说做不了 |
| `unknown` | 结果未知 | 会话不在了或应用重启，无法确认 |

模式（`mode`）与状态正交：`auto` 自主执行、`confirm` 每步等你确认、`readonly` 只读评审。`confirm` 节点交差后停在「已提交待验证」，必须由用户点验证。

### 可实际操作

- **画布**：拖节点改位置、拖空白平移、滚轮与按钮缩放、适应窗口、按依赖自动分层布局。
- **连线**：进入连线模式后依次点两个节点生成一条依赖边；拒绝自环、重复边与成环（对应 `src-tauri/src/collab/task.rs` 的成环检测），拒绝时当场说明原因。
- **节点**：新建、编辑（名称 / 角色 / Agent / 职责 / 模式 / 验收条件）、删除（连带清理相关边）。
- **干活**：对「待命 · 可继续」的节点派活（生成一条共享任务并开始推进）；运行中的节点可暂停、继续、标记交差；交差的节点可验证通过或退回。合成推进由页面时钟驱动，可关闭。
- **查看**：点节点看详情；「查看转录」打开合成转录弹窗；点前置/后继节点跳过去。

## 可访问性与验证

原生 `button`、`form`、`dialog`；所有图标按钮有名称；连线的可及性由节点详情的「前置 / 后继」列表承载，不依赖读画布。弹窗限制焦点、Escape 关闭并归还焦点；节点可 Tab 遍历、Enter 选中，方向键微调位置。支持 `prefers-reduced-motion`。任意视口无页面级横向滚动。

验证在独立无用户数据的 headless Chrome 中运行 `prototype.case.mjs` 与 `prototype-flows.case.mjs`：断言节点/边的渲染与派生状态、连线拒绝规则、派活到交差到验证的状态机、流程隔离、弹窗键盘行为、窄窗抽屉、双主题与四种视口的无横向溢出、本地资产零 404、无控制台错误、无敏感内容持久化。原型测试不替代真实 WebView、原生窗口拖动与 PTY 连续运行的验收。

## 与现有代码的关系

看板要用到的能力在仓库里都已存在，只是还没有一个「图」把它们串起来：

| 现有能力 | 位置 | 看板怎么用 |
| --- | --- | --- |
| 会话身份与寻址名 | `src/workspace/contracts.ts` 的 `agentName`、`src/collab/contracts.ts` | 节点上的团队角色就是寻址键 |
| 派活投递与回执 | `src/collab/useTaskDelivery.ts`、`src-tauri/src/collab/task.rs` | 「派活」按钮写队列；交差只认 `belfry done` |
| 转包层级与成环检测 | `src-tauri/src/collab/task.rs` 的 `hop` / `path` | 连线模式拒绝成环与自环，理由同源 |
| 房间任务与证据 | `src/rooms/contracts.ts` 的 `RoomTask` / `TaskArtifact` | 节点上的「共享任务」列表 |
| 会话用量与耗时 | `src/usage/session/contracts.ts` | 节点上的 Token 用量与耗时 |
| 转录 | `src/history/details/contracts.ts` | 「查看转录」弹窗的形态 |
| 派活与等待的语义 | `skills/belfry/SKILL.md` | 「派活 → 等交差 → 再派下一个」正是边所表达的东西 |

落地需要新增前端 `src/board/` 与 Rust 侧存储（现有房间任务只在内存里，重启会丢，看板的节点与边同样必须落盘才能跨重启对账）。本原型不承诺这部分已存在。
