# 邮件 AI 助手 · 交互设计与原型交接

状态：交互方案与可点击原型已交付，13 组浏览器验证通过。仅设计原型，不代表生产能力已实现或邮箱已验证。

基线：[brief.md](brief.md)、[delivery-plan.md](delivery-plan.md)、[api-contract.md](api-contract.md) **v0.2**（2026-10-29 最终核对）。
原型：[prototype.html](prototype.html)。负责人：UI。

## 范围与假设

独立后台服务、单用户多邮箱；浏览器用于配置与查看结果。定时执行依赖服务主机持续运行。
设计覆盖 M1 的 IMAP 与摘要闭环，以及 M2 的多账号、Gmail API、Microsoft Graph 和六类任务。
历史导入、附件内容、日报等汇总报告及外部输出均明确标为 M3 后续。

原型持续显示「演示数据 · 未连接真实邮箱或 AI」。所有账号采用 example.test 域名，凭据不可输入真实值。
连接测试、授权、执行和重试仅改变浏览器内的合成状态；刷新或切换演示情境会重置。

## 设计来源与形式

沿用仓库已有 HarmonyOS Sans SC、JetBrains Mono 字体，以及暖白、森林绿、石墨主题；这不表示该服务已经嵌入 Belfry。
界面母题是「来信与回执」：同一条结果始终保留原邮件、任务版本、执行记录三个来源，让 AI 输出可核查。
桌面采用三个固定入口与对照阅读区域；手机导航横排，结果与原文切换阅读，表单逐步展开。
主要目标是连接、配置、运行与恢复的可操作性；工具产品不添加装饰摄影或无来源的统计。

## 信息架构

- 配置：邮箱连接、AI 任务、AI 服务。
- 处理结果：结构化筛选、六类结果、原邮件对照、草稿编辑与复制、显式版本执行。
- 运行记录：独立的 sync / ai 历史、进度、错误和恢复入口。

## 打开与演示

入口为 [prototype.html](prototype.html)，旁边的 `assets/` 需一起保留。已验证直接以本地文件打开，无需安装前端依赖或构建应用。
也可以从仓库根目录启动只服务原型文件的本地预览：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/design/mail-ai-assistant
```

然后打开 `http://127.0.0.1:8765/prototype.html`。

默认「日常工作」提供两份演示邮箱、六种模板、六份结果。左下角的「演示情境」在手机上位于导航上方。
切换情境会重置全部内存状态；不会读取浏览器已登录的邮箱。
「演示选项」中可切换暖白、石墨、紧凑阅读，或指定下一次连接测试成功、认证失败、网络失败。

建议用以下顺序验收：

1. 选择「从零开始」→ 连接第一个邮箱 → 选择 IMAP → 填写演示名称和地址 → 模拟测试 → 保持默认五分钟、定时未开启。
2. 保存并配置任务 → 配置演示 AI 服务 → 模拟测试服务 → 选择摘要 → 绑定邮箱 → 预览示例并保存。
3. 在邮箱配置中开启／暂停定时，观察连接健康仍保持正常。点击「立即检查」后查看同步进度。
4. 进入处理结果，查看摘要、原邮件、附件元数据和运行版本。再次立即检查得到「同步正常，暂无新邮件」。
5. 选择「单任务失败」→ 查看失败任务 → 重试 → 查看新增的成功结果；其他成功结果始终保留。
6. 编辑已有任务的处理要求，再对已保存邮件运行新版本。新结果与原结果同时存在；同版本再次执行返回原运行。

## 页面与交互规则

### 配置：邮箱连接

用同一个三步向导处理 IMAP、Gmail API 与 Microsoft Graph：选择服务商 → 测试连接 → 同步设置。
服务商只决定授权方式、连接字段和能力阶段，不决定独立页面。

- IMAP 使用名称、账号、服务器、直接 TLS/993 与演示授权码。真实凭据需在独立秘密输入通道提交。
- Gmail / Graph 演示官方授权，使用合成账号标识。真实创建接口只提交 provider/name，账号身份应来自授权回调；不能信任用户自填邮箱作为认证结果。
- 连接测试使用独立记录，展示排队、进行中、成功或失败。测试过程中保留上次连接健康。
- 邮箱卡分别显示 `connectionState` 与 `syncPolicy.enabled`。定时默认关闭；界面接受 1–1440 的整数分钟，提交时换算秒，默认 300 秒。
- 首次启用或首次手动检查固定激活边界。暂停、改频率、恢复授权均保留这个边界。只处理激活后收到的 Inbox 邮件，已读状态不影响导入。
- 新连接在「模拟测试」时创建，取消后可在列表中看到已创建的未启用配置。成功测试后也不自动开启定时。
- 上次成功、下次计划、连接状态分别展示。授权异常时显示恢复入口；恢复连接不会把旧失败运行改成成功。

原型每个邮箱的首次手动检查会模拟一封**激活后新到达**的邮件；再次检查返回零新增。
这用于演示去重，不是历史邮件导入、IMAP 协议校验或真实游标验证。

### 配置：AI 服务与任务

AI 服务配置包括名称、部署适配器、演示地址、模型与本配置的占位凭据。测试只模拟固定短样本生成与结构校验。
与 v0.2 对齐，测试记录带 `configVersionId`。修改地址／模型生成新配置版本；已有任务继续引用旧配置，编辑任务时需显式勾选「采用 AI 服务的最新配置版本」。
真实新配置默认未配置凭据、未测试；只有明确写入本配置的凭据并测试通过后，才可以显示正常。原型的成功状态来自演示占位凭据，未实现真实密钥绑定。

任务向导为「选择模板 → 设置名称、来源邮箱、处理要求及可选条件 → 预览 → 保存」。一个任务一种模板，一个任务可绑定多个邮箱，一个邮箱可绑定多个任务。

| 模板 | 界面参数 / 结果 | 对应枚举 |
| --- | --- | --- |
| 邮件摘要 | 中文摘要、关键点；长度可写入处理要求 | `summary` |
| 邮件分类 | 自定义标签、分类依据、模型置信度；未匹配保留未知 | `classification` |
| 提取待办 | 行动、负责人、截止日期、原文引用；未知显示「未提供」 | `todo_extraction` |
| 提取字段 | 字段名称与类型；未提供的值保持 null | `field_extraction` |
| 邮件翻译 | 目标语言、译文、原邮件 | `translation` |
| 回复草稿 | 主题、正文、用户编辑稿、模型原稿 | `reply_draft` |

摘要是 M1 计划验证模板；其余及多账号配置属于 M2 扩展演示。日报是 M3 的聚合报告，不作为逐封模板混在这个枚举中。

筛选支持发件人域名、主题关键词、是否含附件。不同维度取 AND，同一数组内取 OR；空值不限制。
模型名称、temperature、maxOutputTokens 放在展开项中，真实可用字段按适配器校验。

任务规则变更产生不可变版本；改名或暂停只更新 revision。绑定使用 `future_ingest`，只影响生效后首次入库的邮件。
保存／启用绑定不会追溯已保存邮件；暂停不取消已排队运行。原型的「预览示例输出」是本地固定样例，不是 AI 调用或保存动作。

### 处理结果

结果页使用邮箱、模板、具体任务、生成时间四个结构化筛选，结果列表按每份结果组织，支持一个邮件多个任务／版本。
原型提供全部时间与演示当天；任意日期区间和游标分页留在真实 UI 接入中完成。

桌面详情保留结果与原邮件对照区域；较窄设备使用「AI 结果 / 原邮件」切换。
手机点击结果进入单条阅读，可返回列表，筛选器暂时收起以留出阅读空间。

- 结果头部显示任务名、版本和生成时间；页尾可打开对应运行。
- 邮件正文以安全纯文本展示。附件只列文件名、大小与「内容处理 · 后续」。
- 失败不生成 `Result`，只在运行记录中出现。结果页的异常提示跳到 AI 失败记录。
- 「对这封邮件显式运行」显示选定任务及最新版号。同版本已有运行则返回原记录；失败需去重试原运行。
- 新任务版本生成新运行与结果；旧版本结果保留，不能用新结果覆盖旧结果。
- 「导出结果」在浏览器下载带 `demonstration: true` 的单份 JSON；不会请求额外导出接口。

### 回复草稿

模型原始 `output` 保持不变，编辑器使用单独的 `draft`。修改后显示「有未保存的修改」。
保存更新 draft、revision、status=edited；原输出可在展开项里对照。

复制正文使用编辑器当前文字；复制主题与正文按 `主题：…\n\n…` 组合。
未保存的文字可以复制，提示「当前修改尚未保存」；复制不会保存、调用 AI 或发送邮件。
浏览器不允许剪贴板访问时弹出保留全文的选中文本框，用户可键盘复制。

「草稿编辑冲突」情境模拟 412：保留用户文字，同时可查看服务端版本。
用户可「保留我的文字继续编辑」以取得最新 revision，再手动保存，或选择采用最新保存内容。
没有自动覆盖冲突文本或发送邮件的按钮。

### 运行记录与恢复

`kind=sync` 与 `kind=ai` 共用运行列表，不共用状态语义。筛选 AI 时不会出现 partial。
同步只显示已持久化邮件数、已排队 AI 数、已跳过重复数；不以未知总量计算虚假百分比。
同步成功不等于 AI 已成功，单项 AI 失败不会倒改同步状态。

| 情境 | 展示与恢复 | 演示入口 |
| --- | --- | --- |
| 无配置 / 无结果 | 引导连接、配置、运行；筛选无匹配时提供清除筛选 | 从零开始 / 结果筛选 |
| 测试、同步或 AI 执行中 | 排队 → 进行中 → 终态；展示已完成数量 | 正常流程 |
| 成功但零新增 | 「同步正常，暂无新邮件」，不提示故障 | 没有新邮件 / 重复检查 |
| 邮箱授权失效 | 恢复授权 → 模拟测试 → 保存 → 显式重试旧失败运行 | 授权失效 |
| 网络同步失败 | 保留其他邮箱和既有结果；重试原同步，累计 attempt | 同步失败 |
| 一个 AI 任务失败 | 原邮件及其他结果仍可读；重试原版本，不混用新任务版本 | 单任务失败 |
| 等待自动重试 | 显示 nextAttemptAt，没有另开重试按钮；演示面板可推进时间 | 等待自动重试 |
| IMAP 身份歧义 | partial 同步 → 比较候选 → 关联已有或保留独立邮件 | 邮件身份待确认 |
| 草稿 revision 冲突 | 保留本地文字、展示服务端内容、用户选择处理 | 草稿编辑冲突 |

IMAP 确认「同一封」产生 linked，不重复执行同版本任务；「不同邮件」产生 kept_separate，保存新邮件并按当前绑定排队。
原 partial 运行保留历史，待判定项处理后可开始新的增量检查。
重试保留同一个 run.id、taskVersionId、最初 trigger 与历史尝试；领取执行时 attempt 增加。
发现已有更新同步时转到新运行，避免在过期上下文继续重试。

## 字段与动作对照（API v0.2）

| 界面对象 / 动作 | 对应接口与关键字段 | 原型处理 |
| --- | --- | --- |
| 能力阶段 | `GET /capabilities`；executionMode、available、implementationStatus、stage | 固定 simulated；所有提供方 planned / available=false；界面显式标注模拟 |
| 邮箱连接 | `GET/POST /mailboxes`；provider=`imap/gmail/graph`、accountEmail、connectionState | 一个向导，多份独立资源；OAuth 演示身份不作为真实认证结果 |
| 连接测试 | `POST /mailboxes/{id}/tests`、`GET /connection-tests/{id}` | 独立 queued/running/succeeded/failed 记录与检查项 |
| 同步策略 | `PATCH /mailboxes/{id}/sync-policy`；enabled、intervalSeconds、folders、activatedAt | 定时与连接健康分别保存，边界不随暂停重置 |
| Gmail / Graph 恢复 | `POST /mailboxes/{id}/authorizations` → 回调／查询状态 | 只模拟授权；正式版本依据 M2 能力开关开放 |
| AI 服务 | `/ai-services` 与 `/config-versions/{configVersionId}` | 展示当前服务配置；测试携带固定 configVersionId；旧版本凭据界面见缺口 |
| 任务与绑定 | `/tasks`、`/tasks/{id}/versions`、`/task-bindings` | definition、currentVersion、revision、effectiveFrom、appliesTo=future_ingest |
| 立即检查 | `POST /sync-runs`，mailboxId | 同邮箱活动运行复用，模拟新邮件持久化后才排队 AI |
| 手动执行已存邮件 | `POST /messages/{id}/task-runs`，taskId + taskVersionId | 同邮件同版本唯一；新版本另建结果 |
| 运行历史 | `GET /runs`、`/sync-runs/{id}`、`/ai-task-runs/{id}` | kind 决定详情；状态、attempt、phase、progress、error 分别展示 |
| 重试 | `/sync-runs/{id}/retry`、`/ai-task-runs/{id}/retry` | 重用原运行、任务版本与尝试历史 |
| 结果与原文 | `/results`、`/results/{id}`、`/messages/{id}` | ready/edited 结果与 available 纯文本；null 保持未知 |
| 草稿 | `PATCH /results/{id}/draft` + If-Match | 模拟 revision 冲突；output 不变，draft 独立 |
| IMAP 待判定 | `/mailboxes/{id}/recovery-items`、`/recovery-items/{id}`、`/resolve` | 两种决定均可点击，status=pending/linked/kept_separate |
| 错误提示 | error.code / message / retryable / action / details | 按失败步骤给恢复动作；详情只显示诊断码及来源 ID |

真实接口适配层必须携带登录会话、CSRF、POST Idempotency-Key 与可变资源 If-Match；原型没有伪造 HTTP 成功响应。
M1 活动运行按契约轮询、失焦降频、终态停止。原型用本地定时回调展示进度，不实现后台五分钟调度。
`cancelled` 是保留状态，本原型不显示没有接口支持的运行取消按钮。

## 契约缺口与待实现界面

以下是已明确的边界，不把原型交付当成真实联调通过。

| 项目 | 已有内容 / 尚缺内容 | 负责人 / 实现要求 |
| --- | --- | --- |
| AI 配置版本凭据恢复 | 已对齐测试携带 configVersionId、任务显式采用新配置；尚未演示旧配置版本列表、轮换、撤销以及 CONFIGURATION_CHANGED | UI 按 v0.2 §5.1 补入口；AI_SERVICE_AUTH_REQUIRED 应跳到 error.details 指向的原配置版本，修复后重试原运行，不能仅修改当前任务 |

| 身份比对正文 | 两种恢复动作与候选限定已演示；原型使用恢复项 bodyText | 后端明确恢复项详情的完整 DTO；UI 补内容不足／过期而不可判定的页面 |
| 内容过期与保留期 | 阅读渲染有不可用提示与禁用执行保护；没有专门的过期情境、保留期设置、24 小时清理提示 | UI 按 §3 / §7 补设置与墓碑场景；项目经理确认实际保留期 |
| 错误与并发覆盖 | 已演示四类必需状态、等待重试、身份确认及草稿 412；没有穷举所有 401/403/409/422/429、队列背压与跨页并发 | 前后端按错误契约实现；保持用户输入，分别验证来源不可用、被新同步接管、凭据失效等情况 |
| 导出与复制 | 浏览器本地复制、降级选择文本、单份 JSON 导出 | 无额外后端导出接口；批量导出与外部发送另立需求 |
| 实时与长列表 | 模拟数据一次载入，本地回调推进进度 | 接入游标分页、任意日期区间及活动运行轮询；不依赖 SSE |

## 视觉、布局与可访问性

- 正文使用已有的 HarmonyOS Sans SC；时间与版本使用 JetBrains Mono。品牌与字体资产、来源、许可见 [assets/asset-sources.md](assets/asset-sources.md)。
- 暖白为主方案，森林绿用于主操作和选中；石墨与紧凑阅读通过演示面板切换。正文、标签与状态均给出文本，不以颜色独立传意。
- 桌面固定三入口，双区阅读；1550px 以上可在详情内部并排显示结果与原文。850px 以下导航改为顶部；650px 以下使用列表／详情单列，表格改为可读行。
- 表单使用原生 input、select、checkbox、button 和 dialog。Tab 在弹窗内循环，Escape 关闭并恢复发起控件焦点；页签支持左右键、Home、End。
- 提供跳到正文链接、明确表单标签、状态 aria-live、减少动画偏好。移动端主要操作区域至少 40–44px，长文和弹层自然滚动。
- 邮件正文、输出和用户编辑均转义显示；CSP 禁止连接外部服务与提交表单。没有 localStorage/sessionStorage 凭据或邮件持久化。

验证入口：[assets/prototype.test.mjs](assets/prototype.test.mjs)，夹具：[assets/browser-fixture.mjs](assets/browser-fixture.mjs)。
使用仓库已有 Chrome CDP 包装器，临时浏览器 profile、本地静态 HTTP 服务及浏览器指针／键盘事件。
