## Goal

将 `docs/design/belfry-ui/` 中 Graphite 主方案的视觉与信息层级落地到 Belfry 现有生产 React 界面，使用户从正常应用入口运行 Belfry 即可看到新 UI，而不是只能打开独立 HTML 原型。

覆盖所有 Belfry 宿主界面：工作台、侧栏、工具栏、终端标题与分屏外壳；项目库、命名工作区、SSH；Quick Open、协作、文件/Git、历史、用量；设置全部现有栏目与细粒度控件、全局/项目 Provider、插件中心/启动器/工作面板外壳；通用弹窗、确认、错误、空状态和更新界面。统一石墨深色与暖白主题、排版、间距、控件和键盘焦点。保留终端中心定位和现有功能，不将产品替换为演示程序。

## Acceptance criteria

- **生产入口实际生效**：新设计由 `src/` 的生产组件与样式提供，`pnpm build` 的产物呈现新工作台与新设置界面；不依赖打开 `docs/design/belfry-ui/index.html`、iframe 原型或修改后的截图。交付列出实际修改的生产文件及入口。
- **全局覆盖可核对**：交付一份宿主 UI 覆盖表，逐项列出上述模块、对应生产组件及已执行的检查；所有现有设置栏目和细粒度控件保留并应用统一设计。未修改的第三方插件内部页面明确排除，不能将其计为已改造。
- **真实业务契约保留**：生产代码继续使用现有 IPC、状态与数据来源，不出现原型的固定项目、合成用量或伪终端来替代真实功能。保留 Provider 保留/替换/清除、敏感预览显式确认、配置损坏停止写入，以及 Claude/Codex/Pi 各自的生效语义。
- **自动回归通过**：新增或更新相关 UI 定向测试；`pnpm test`、`pnpm build`、`node .github/workflows/verify-plugins.mjs` 均通过。插件回归不得因缺浏览器而静默跳过。若确需修改 Rust 生产代码，准备 CLI sidecar 后执行 `cargo test --workspace --locked`，在专用 HOME、CLI 配置及临时目录下运行。
- **生产浏览器证据**：使用生产构建及明确标注的测试原生命令适配，留下工作台、设置/Provider、插件中心、协作、文件/Git、历史/用量、项目/SSH 和通用弹窗的实际截图与交互结果；不是独立设计原型截图。覆盖深浅主题、1440×960、1024×768 与窄内容区，以及长名称/路径，不出现页面级横向溢出或无法触达的主要操作。
- **关键行为有测试证据**：验证面板打开/关闭及主题切换不卸载现有终端，不重复创建终端；会话选择、分屏、Quick Open 键盘操作、弹窗焦点归还、未保存保护、Provider 敏感预览门禁、协作待确认入口和生产懒加载故障恢复保持可用。模拟原生命令测试与真实 PTY/桌面检查分别报告。
- **验收表述准确**：检查修改文件的格式/差异；报告执行命令、通过/失败/跳过和截图位置。当前环境无法执行的 Windows 原生、真实 Tauri WebView 或系统缩放检查须列为未验收，不能用浏览器模拟结果冒充全平台通过。

## Boundaries

- 保留当前 M1 凭据保护和工作区内全部无关/并行修改，不重置、不覆盖、不提交其他会话的工作。
- 不读取真实用户凭据、生产 API 配置、项目正文或终端历史作为设计/测试材料；测试只用专用临时目录与合成数据。不启动会触发真实用户库迁移的桌面实例。
- 不改变终端输入、生命周期、项目隔离、恢复、后台会话、权限与插件安全边界。若 UI 需要调整状态编排，只限实现上述交互所必需的变更并提供回归证据。
- 不删除现有功能或用户主题/字号/壁纸偏好，不将原型里省略的细粒度功能当作生产删除依据；不增加账号、SSO、云同步或遥测。
- 不改造第三方插件自有内容，不承诺 OS 沙箱。Paper/Compact 保留为设计参考，本次以 Graphite 统一双主题落地，不额外新增三套产品模式。
- 不进行真实凭据迁移、正式发布、签名证书操作或其他 M2–M7 非 UI 工作。原生环境缺失只限制相应验收，不阻止完成可验证的生产前端落地。
