## Goal
在保留现有视觉风格、业务行为和左侧栏布局修复的前提下，完成用户指定的六类优化：会话列表 hover/点击反馈、分组展开收起高度过渡、统一弹窗与抽屉动效、按钮按压反馈、协作及历史面板滑入滑出，以及有测量依据的 React 无效渲染优化。

本轮弹窗重点覆盖通用确认框和 Quick Open，抽屉重点覆盖协作面板和历史面板；按钮反馈覆盖侧栏、工作台工具栏及上述弹层的操作按钮，不包含系统窗控、分屏拖动手柄或第三方插件内部界面。

## Acceptance criteria
1. **列表与按钮反馈**：会话行具有 hover、按下及选中状态反馈；范围内按钮具有轻微缩放和阴影/底色反馈，禁用状态不响应按压。反馈不改变布局占位，不延迟实际动作，不影响会话拖拽或行内重命名。
2. **分组过渡**：多项目会话分组展开、收起均有连续高度过渡，箭头状态同步；快速反复切换至少 10 次后以最后一次操作为准，无残留占位、内容截断或不可见控件获得焦点。
3. **统一弹层动效**：通用确认框和 Quick Open 有进入、退出过渡；协作及历史面板有滑入、滑出过渡，使用统一的动效时长与曲线规则，单次过渡不超过 280ms。关闭、重新打开或切换面板不留下遮罩、重复面板或错误占位；原有 Esc、外部点击、焦点恢复行为保持有效，确认动作不重复执行。
4. **减少动态效果**：启用 `prefers-reduced-motion: reduce` 时，本轮新增位移、缩放和高度动画关闭，功能仍正常，关闭与焦点恢复不依赖动画事件才能完成。
5. **布局与终端保护**：在暗色、亮色以及 1888×1070、1440×960、820×500 窗口下，侧栏展开时满高、工具区贴底、长会话列表独立滚动，菜单不被侧栏裁切；侧栏收起、右侧面板开关及进入设置不产生主区域换行或横向溢出。开合期间已有终端 DOM 与会话保持存活，输入仍可用，不因动画逐帧改变终端列数或发送 PTY resize。
6. **性能证据**：提供同一环境、相同会话数据和操作序列下的优化前后记录，覆盖侧栏开合、会话切换及拖拽。至少一个已确认的 React 热点，其无关组件渲染次数或高频状态提交次数减少，并有对应回归测试；报告具体计数，不以新增动画作为性能提升证据，不承诺未经测量的帧率。
7. **验证通过**：`pnpm build`、`pnpm exec vitest run`、`node --test src/components/lazy/testing/sidebar-layout.case.mjs` 及本轮新增的交互/性能回归测试通过。浏览器测试使用隔离的合成会话数据，记录操作、布局断言和错误检查；明确区分浏览器模拟原生接口验证与真实桌面运行验证。

## Boundaries
- 保留工作区内已有且无关的用户改动，不重置文件或进行大范围视觉重设计。
- 不修改 Rust 后端、会话持久化协议、Provider 配置、真实凭据或用户数据；不关闭、重启用户正在运行的终端和 Agent 会话。
- 不为动画卸载重建终端，不对整个终端画面做缩放、淡出或持续宽度动画来掩盖卡顿。
- 不扩展到第三方插件内部动效、全应用缓存/虚拟列表重构或平台安装包发布；不引入大型动画依赖。
- 仅修复本轮交互及其回归验证所必需的问题。若运行环境确实阻碍验证，报告具体未通过项目和证据，不宣称已完成。
