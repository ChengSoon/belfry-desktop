# Belfry 企业化与核心体验优化计划

## 1. 目标与实施边界

保留 Belfry“本地优先的多项目、终端与 CLI Agent 工作台”定位，按 **安全与可信交付 → 核心体验 → 诊断与持续维护** 的顺序优化，不做全盘重构。

本计划包含完整路线图；**批准后首次只实施 M1「Provider 凭据保护」并完成验收**，不自动推进其余里程碑。证书采购、线上发布、真实凭据迁移和后续阶段另行确认。

共同约束：
- 不读取或使用真实用户密钥、生产 API 配置与终端记录；开发和测试使用合成数据、临时目录和模拟接口。
- 保留现有工作区恢复、终端持续运行、配置损坏保护、设置未保存保护和懒加载恢复行为。
- 不改变 CLI Agent 原有配置规范，不声称外部 CLI 明文配置已被一并加密。
- 不新增账号体系、SSO、云同步、全量遥测、插件强沙箱或大规模视觉换肤。
- 每个里程碑独立提交、独立验证，不将安全迁移与 UI 重构混为一个大变更。

## 4. M1：Provider 凭据保护（首轮执行）

### 4.1 实施内容

1. **拆分存储模型与运行时模型。** Provider 元信息与秘密分离：持久化 JSON 保留非敏感字段、格式版本和凭据引用；API Key 与备份 OAuth 内容不再直接序列化到主库。不得因简化迁移而删除未知 Agent 配置。
2. **增加安全存储适配层。** 采用系统安全存储保护随机主密钥，使用成熟库提供的认证加密保存秘密载荷；macOS 对接 Keychain，Windows 对接系统凭据存储。OAuth 内容不直接塞入具有大小限制的单个系统凭据条目。不自制密码算法、不把主密钥与密文并存于普通配置文件。
3. **设计版本化、可重试迁移。** 读取旧库 → 在安全存储写入并校验秘密 → 原子提交新格式。提交前失败保留旧库、不覆盖；提交后重试不得生成重复记录。不得自动额外创建明文备份。未知版本、损坏 JSON 或无法完整识别的秘密结构，停止迁移并报告，不猜测性转换。
4. **明确不可用行为。** 钥匙串拒绝/锁定、解密失败、引用丢失时给出可恢复错误，不静默回退明文、不覆盖已有数据。迁移未完成时阻止相关 Provider 写入/切换，不影响无关的工作区和终端操作。
5. **保持外部 CLI 兼容。** 服务层仅在需要应用配置或启动 Agent 时获取秘密；保留官方/三方切换、项目覆盖和 Codex 官方认证恢复语义。明确外部 CLI 文件仍可能按其要求保存明文。
6. **收敛秘密暴露。** 列表/状态响应只返回“已配置”等必要信息；编辑采用保留、替换、清除的明确语义，避免用空字符串或掩码覆盖真实秘密。检查错误、Debug 输出、事件及插件接口，阻止非必要的原始密钥传播。
7. **处理删除与兼容。** 元数据更新成功后再清理不再引用的秘密；清理失败可重试且不泄露内容。记录旧版不能读取新格式的边界；不自动通过明文导出实现降级。

### 4.3 验收标准

- 使用合成 API Key/OAuth 数据，完成旧格式迁移、重启读取、更新、删除、全局切换、项目覆盖及官方认证恢复测试。
- 新格式主库、常规返回值和日志中不含合成秘密；安全载荷不可明文读取。外部 CLI 测试配置为明确记录的例外。
- 注入系统存储拒绝、磁盘写入失败、原子提交失败、解密失败、凭据缺失与进程中断，验证不覆盖原配置、不丢失可恢复数据、不静默降级。
- 测试未知 Agent、未知版本、损坏 JSON、重复迁移和孤立凭据清理。
- 使用 mock secret store 执行确定性自动测试；macOS/Windows 原生系统存储另做合成凭据的集成冒烟，并清理测试条目。
- 不仅以“加密函数测试通过”宣告完成：必须通过完整 Provider 使用路径回归。

## 5. M2：可信发布

### 行为与文件
- 扩展 `.github/workflows/release.yml` 与 `src-tauri/tauri.conf.json`，接入 macOS Developer ID 签名、公证、票据验证，以及 Windows 发布者签名和时间戳。
- 覆盖应用、安装包及需签名的内嵌可执行产物；保留 updater 签名和现有草稿发布机制。
- 扩展 `.github/workflows/release-assets.mjs` 及相邻测试；平台原生步骤负责验证实际签名，产物检查不能代替签名验证。
- 更新 `README.md`、`README.en.md` 和发布文案，只在验证成功后移除未签名说明。

### 验收与外部依赖
- macOS 使用原生签名/Gatekeeper/公证验证；Windows 使用原生 Authenticode 验证。
- 全新安装与已有版本更新分别验收；不承诺签名后必然立即消除 Windows SmartScreen 声誉提示。
- 正式发布缺少证书、Secrets 或验证失败时保持草稿/失败关闭，不默默发布未签名包。
- 用户需在平台后台配置证书和 Secrets；不要求把证书私钥贴入聊天。证书尚未确认可用，是发布验收的外部前提，不阻塞 M1。

## 6. M3：安全边界与插件治理

### 行为与文件
- `src-tauri/tauri.conf.json`、`src-tauri/capabilities/`：按实际窗口、资源和命令使用情况收紧 CSP 与权限；不盲目复制一份通用严格策略。
- `src-tauri/src/provider/commands.rs`、相关文件/终端命令模块：检查来源、参数和授权范围。区分主应用主动访问任意用户项目的能力，与受限插件应遵守的根路径边界。
- `src-tauri/src/plugins/`、`src/plugins/PluginPanel.tsx`：展示插件来源、版本和实际权限；区分本地开发插件与已知来源插件；提供明确确认、禁用与恢复路径。
- 新增安全边界说明，明确 Node worker 不等于操作系统沙箱；本阶段不宣称能安全运行任意恶意插件。

### 验收
- CSP 下终端、字体、壁纸、Markdown、文件预览、插件界面、更新和懒加载均可正常使用。
- 针对不可信内容发起的未授权调用，增加拒绝用例；针对路径操作覆盖穿越、符号链接与 Windows 路径语义等实际相关边界。
- 插件禁用后不能通过重启恢复流程意外再次激活；现有合法插件回归通过。

- 使用相同场景多次比较，不能以降低打包体积但拖慢首个终端为成功。性能预算在取得基线后确定。

## 10. 每个里程碑的检查与发布规则

1. 新增/修改模块先跑定向测试，再运行 `pnpm test` 和 `pnpm build`。
2. 涉及 Rust：按现有 CI 先准备 CLI sidecar，再在 `src-tauri` 下运行 `cargo test --workspace --locked`。
3. 涉及插件、面板或 CSP：运行 `.github/workflows/verify-plugins.mjs` 中对应回归；生产懒加载恢复继续通过。
4. 保留 `.github/workflows/checks.yml` 的 macOS/Windows 矩阵和现有 Node 20 定向兼容测试。
5. 平台凭据、安装更新、真实 WebView 和视觉交互必须完成对应原生/浏览器验收；模拟接口测试不替代这些检查。
6. 测试输出、截图和性能数据不得包含真实用户秘密。临时材料放会话 scratch，项目内仅保存任务相关测试和说明。
7. 每次交付报告修改范围、实际执行的命令、结果及未验证项。环境缺失时报告限制，不将跳过写成通过。
