# 会话协作

多个 Agent 可以在同一项目中分工：一个负责前端，一个负责后端，任务、补充输入和结果通过 A2A 交换。围绕长期需求，可以创建房间，由统筹管理成员与共享任务板。

:::note 版本说明
本页对应 1.0.10 起提供的 A2A 客户端、本地网关、显式报告与 Skill 迁移。自动本地适配范围是 MCP 注入的 Codex PTY / Claude PTY；真实模型自主执行和远端服务尚未验收。已打开的 CLI 会话需重开以取得新工具；1.0.9 及更早版本不包含这些改动。启动、外部服务配置和验证边界见 [A2A 连接](./a2a.md)。
:::

## 稳定的会话名

为 Agent 会话设置一个**稳定名字**，比如 `前端`、`测试`。名字在项目内唯一，重开会话也保留。普通派活按侧栏的会话名选择目标；房间消息按房间角色名选择收件人。这些名字由你设置，不随界面语言改变。

在侧栏命名了 `reviewer`、`前端`、`测试` 等会话后，对 Agent 说“交给前端”，指的就是那条会话。

## 通过 A2A 派活

运行中、实际接通协作工具的本地 Agent 自动出现在当前项目的可用连接中。外部 Agent 在 **项目顶部 A2A → 外部连接** 中配置兼容的 Card 和静态认证。普通 CLI 需要实际适配器；以发现结果显示的可用性为准。

可以直接向当前 Agent 提出需求：

> 列出当前项目可以协作的本地 Agent 和已配置的外部 Agent，说明各自能力。把“运行登录回归，并报告失败原因”交给测试，间隔查询进度，完成后展示结果。

Sender 发送指定文本，使用返回的宿主句柄查询、续写或请求取消。Recipient 从工具读取完整任务与必要上下文，显式报告正在工作、需要输入、已完成或失败，并提交文本结果。任务提示会提供对应的报告句柄、代次和工具；日常协作不需要读取 Belfry 协作 Skill 或运行独立协作 CLI。

“已提交到终端”只表示投递成功。任务完成以 Recipient 的显式报告为准；终端空闲不能证明完成。需要输入时，Sender 在原任务上补充文本；超时只结束当前等待，不会完成或取消对方的工作。

任务按接收方排队。对方忙碌、等待确认或不可用时，投递暂停；可以接收后再提交。不要因查询超时自动重复发送初始任务，服务可能已经接受它。

## 房间与共享任务板

从侧栏「协作房间」创建房间，选择统筹和成员，填写目标、当前重点与约束。统筹拆解需求、分配任务、跟进进度；成员处理自己负责的任务，并报告结果或所需帮助。

Agent 通过授权的上下文工具读取所属房间的简报、成员、任务板、待回复和消息。房间任务仍使用 `T1`、`T2` 等业务编号，区分待开工、进行中、已完成与归档，并可指定前置任务。

例如，对统筹说：

> 读取这个房间的需求和成员职责。在任务板给后端创建“实现登录接口”，完成标准为“接口回归通过并记录调用方式”；再给前端创建“接入登录界面”，以前一个任务为前置条件。

成员通过工具读取分配任务，报告进度和结果。需要别人配合时，记录原因并向统筹发消息。统筹可按权限调整负责人、重开或归档任务；归档影响任务板，房间历史仍保留。

房间任务编号、Sender 查询句柄和 Recipient 报告句柄分别承担业务记录、查询和报告职责。Agent 使用宿主返回的正确句柄和当前代次；另一会话、旧实例或旧任务代次不能代交结果。

### 消息与暂停

可以对成员说：

> 给后端发送“请确认登录接口参数”，要求回复，并保留这条消息的编号。

未指定收件人时，成员默认发给统筹，统筹默认发给全体。指定角色或群组仍遵守房间原有角色与权限规则。消息工具可携带主题、问题与答案编号。

暂停房间后，消息继续记录，停止向成员终端投递，空闲提醒也暂停。已经开始的工作继续执行。

## 待回复与完整消息

要求回复的消息会保留待回复事项。Recipient 从消息工具读取原文，用原消息编号及相应问题编号明确回复。回复问题和完成任务是两步独立操作；完成任务不会自动回答所有消息。

房间「待回复与按编号回复」入口可打开原文、引用并回复。完整编号或无歧义的短编号都可定位。早期待回复即使离开最近 1000 条消息窗口，重启后也仍可查询。

超长终端提示会引用完整消息；Agent 按提示使用消息读取工具取得全文后再行动，无需协作 CLI。

## 投递阶段

协作面板显示投递阶段与显式工作结果，房间对话显示各成员的消息投递情况。

| 阶段 | 含义 |
| --- | --- |
| 已受理 | 任务已保存，尚未进入目标终端队列 |
| 排队中 | 等待目标会话可以接收 |
| 正在提交 | 等待终端回执 |
| 已提交到终端 | 终端确认提交，等待 Agent 的显式进度或结果 |
| 提交结果不确定 | 指令可能已经写入终端，需要核对，不会自动重复粘贴 |
| 投递已取消 | 这次投递已放弃；结果不确定时仍可能已经写入终端 |

不确定投递先点击「去目标终端核对」。确认已经出现指令后，再选择「确认已提交」；Agent 仍需报告结果。选择「放弃此任务」不会撤回已写入的指令或停止已经开始的工作。

本地 HTTP 请求停止、排队撤回和远端任务取消分别处理。运行中任务无法安全停止时，A2A 会明确返回不可取消，不能把尝试取消当成成功。

## 重启与历史

房间、业务任务和投递记录保存在本地。已提交任务不自动重投，不确定投递保留到人工核对。A2A 句柄绑定当前项目、连接与 Agent 实例，重开的实例需要重新发现连接并读取授权上下文。

房间主时间线保留最近 1000 条消息，从顶部「加载更早历史」可逐页浏览原文；待回复入口独立保留早期未完成事项。新消息到达时保留当前阅读位置。

房间信息显示历史大小。历史原文保留到删除房间，需要长期保存时先备份应用数据目录。当前没有归档旧历史的操作，手动删除账本会损坏房间数据。

删除房间会同时关闭并删除房间内所有成员的 Agent 会话，包括统筹，成员不会回到普通会话列表；刷新或重启后也不会恢复。已经移出房间的会话继续保留。

## 环境诊断与 Skill 迁移

设置页的协作环境检查 CLI、登录或 Provider 状态及协作通道。A2A 本地发现还会说明哪些运行会话真正接通适配器；CLI 可启动与可接收 A2A 任务分别核查。

新宿主停止安装 Belfry 协作 Skill，并迁移移除与内置中文或英文内容完全一致的旧副本。用户自行修改的副本会保留并报告。其他插件提供的 Skill 和通用 Skill 功能继续可用。

完整工具参数、兼容范围与本地试用见 [A2A 连接](./a2a.md)。
