# 会话协作

如果你同时开着几个 Agent 会话，可以让它们**互相配合**：一个负责前端、一个负责后端，中间不用你人肉传话。

## 稳定的会话名

协作的前提是能叫得出名字。为 Agent 会话设置一个**稳定名字**（比如 `前端`、`测试`），这个名字在整个项目内固定，重开会话也保留。

> 在 Belfry 侧栏开好并命名了几条会话（reviewer、前端、测试这类），本身就是让协作派活有明确目标的信号。**说「交给前端」指的就是那条会话。**

## 内置 belfry CLI

协作通过应用内置的 `belfry` 命令行完成，在同项目的会话之间：

- **send** — 把活派给某条会话
- **wait** — 等对方做完
- **done / fail** — 交差或报告失败

任务**按目标 Agent 分别排队**。对方忙碌或正在等待确认时暂缓投递，回到空闲后按顺序发送——不会把消息插进它正在进行的对话里。

## 批准闸门

协作任务可以设置**批准闸门**：敏感操作先经你点头再执行。另外还有**循环与层级限制**，防止会话之间互相无限派活套娃。

## 协作状态面板

一个面板看全：谁在等谁、排队中几条、哪些已交差。

## 环境诊断

协作依赖一套运行环境（Belfry skill、CLI 登录态、协作通道）。设置页提供**诊断**：

- Belfry skill 是否就位、是最新版吗
- Codex / Claude Code 的登录与功能状态
- doctor 结果与协作通道连通性

诊断可以**自动同步或手动更新**内置 skill。三个客户端分别报告状态，**保留部分成功结果**——比如 Claude 正常而 Codex 没登录时，不会因为一个失败就全盘报错。
